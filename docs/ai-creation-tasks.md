# AI 工作台：持续完成目标的创作任务

## 使用

AI 导演输入框上方增加「本次目标」：自动识别、编写完整剧本、制作完整分镜、讨论与局部修改。

- 完整剧本：从想法、附件或已有剧本生成完整剧本草稿，不提前创建幕。
- 完整分镜：完整剧本 → 全部幕规划 → 逐幕镜头 → 完整性检查。分批自动推进，不需要逐轮回复「继续」。
- 讨论与局部修改：保留原聊天、工具提案和逐条审阅入口。自动识别会优先将局部修改、检查、指定某一幕的操作留在这条路径；可手动选择目标消除歧义。
- 「制作完整分镜」按钮与发送完整创作目标走同一任务服务，不再要求为了继续生成而开启免确认。

任务卡显示阶段、已完成幕数、镜头数和完整草稿。未开启免确认时，全部创作完成后等待「采用完整结果」；开启免确认时，通过检查后自动保存。创作任务本身不提交付费图片、视频生成，也不改原始导入文本。

任务保存创建时的直出 / 制帧模式。制帧模式为每镜生成独立画面计划，采用时写入制帧工作空间；直出模式不创建帧图草稿。

## 恢复与隔离

- schema 26 新增 `creation_run`，持久保存请求、模式、剧本、幕规划、已完成镜头、修复记录与落库检查点。
- 每阶段最多尝试三次；结构、必要意图字段、时长、人物及道具名称、制帧计划不合格时反馈具体错误修复。超过次数后保留草稿，显示恢复入口。
- 暂停会取消当前模型调用，已完成的阶段保留。页面刷新不会停止后台任务；关闭工程或服务停止时取消该工程任务，重新打开后可从检查点恢复。
- 一幕及其全部镜头、角色 / 道具关联、制帧计划和任务检查点在同一事务提交。镜头落库失败会回滚该幕，避免空幕；已成功的其他阶段保留。
- 重试跳过已提交的操作，不重复生成已有阶段；相同请求在工程剧本未变化时复用已完成任务。一个项目同一时间只允许一个未完成创作任务。
- 用户在生成期间修改了工程剧本时，即使开启免确认也转为待审，避免自动覆盖用户改动。
- 原聊天、手动编辑、视频生成及旧同步 autopilot API 保留兼容；主界面的完整创作使用新任务入口。

`Database.atomic()` 仅在当前 asyncio task 内组合现有服务的读写；普通请求保持原事务行为，子任务不继承可操作的 session。模型调用不发生在数据库事务内。

## 接口

- `POST /projects/{pid}/director/tasks`：`message`、`goal`（screenplay / storyboard）、`mode`（direct / frames）、`attachments`。
- `GET /projects/{pid}/director/tasks/latest`：读取项目最近任务并恢复刷新后的界面。
- `GET /projects/{pid}/director/tasks/{rid}`：读取具体任务。
- `POST /projects/{pid}/director/tasks/{rid}/{action}`：pause、resume、apply、discard。

状态：running、review、applying、completed、paused、failed、discarded。discard 只丢弃未采用草稿，不撤销已保存的业务内容。

## 验证边界

自动测试使用模拟模型，覆盖无原文首次创作、完整草稿、审阅采用、关联与制帧计划、失败回滚、有限修复、暂停与重启恢复、重复请求、用户修改保护。另运行既有导演、流式会话、JSON 修复、旧全流程及工程迁移回归。浏览器验收也使用独立工程和模拟响应；真实模型创作质量仍需实际使用评估。
