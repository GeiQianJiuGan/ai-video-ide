# 06 · 打包与分发

本文回答一个问题：**怎么把仓库变成用户双击就能装的安装包。**

目标是**装完就能用**：Python 解释器、后端依赖、FFmpeg 全在包里，用户不需要预装任何东西；
ComfyUI 与 LLM 没配置时手动流程照样走完（硬约束 2 在分发这一层的延伸）。

代码真源：[`scripts/build_desktop.py`](../scripts/build_desktop.py)、
[`scripts/build_sidecar.py`](../scripts/build_sidecar.py)、
[`backend/aivs-backend.spec`](../backend/aivs-backend.spec)、
[`tauri/tauri.conf.json`](../tauri/tauri.conf.json)。本文和代码不一致时以代码为准。

## 0. 一条命令

```bash
python scripts/build_desktop.py
```

先体检、缺什么说什么（不构建）：

```bash
python scripts/build_desktop.py --check
```

默认按当前平台出格式：**Windows → `nsis`（.exe 安装器）**，
**Linux → `appimage` + `deb` + `rpm`**，macOS → `dmg`。要单独出某一种用
`--targets nsis` / `--targets appimage,deb`。

**没法交叉编译**：壳是原生程序，Windows 包只能在 Windows 上出、Linux 包只能在 Linux 上出。
一次拿两个平台的产物走 CI（`.github/workflows/release.yml`：两台机器各跑一次同一份脚本，
推 `v*` tag 时顺带建一个 draft Release）。

## 1. 一个包里装了什么

```
AI Video Studio.exe        壳（Tauri，Rust）——只做三件事，见 tauri/README.md
aivs-backend.exe           后端 sidecar（PyInstaller 单文件，~23 MB）
ffmpeg.exe / ffprobe.exe   内置 FFmpeg（~200 MB，抽帧 / 代理转码 / 导出都靠它）
（前端已编译进壳的资源）
```

三个 `externalBin` 装在同一层——这不是巧合，是 `app/core/ffmpeg.py::bundle_dirs()` 与
`tauri/src/backend.rs::bundled_sidecar()` 共同依赖的约定：壳把自己所在目录用
`AIVS_BUNDLE_DIR` 告诉 sidecar，sidecar 就在那儿找 ffmpeg。

用户数据不进安装目录：release 构建的运行时目录是**应用本地数据目录**下的 `runtime/`
（`settings.json` / `library.json` / `recent.json` / `presets/` 都在那儿），
工程数据在用户自己选的工程目录里。

## 2. 五个步骤，顺序不能换

`build_desktop.py` 按这个顺序跑，因为后面每一步都依赖前一步的产物，而 `cargo tauri build`
会在**编译完十分钟之后**才因为「少一张图标」失败：

| # | 步骤 | 脚本 | 产物 |
| --- | --- | --- | --- |
| 1 | 图标 | `scripts/make_icons.py` | `tauri/icons/*`（`bundle.icon` 列的文件必须都存在） |
| 2 | 内置 FFmpeg | `scripts/fetch_ffmpeg.py --for-tauri` | `tauri/bin/ffmpeg-<triple>` |
| 3 | 后端 sidecar | `scripts/build_sidecar.py` | `tauri/bin/aivs-backend-<triple>` |
| 4 | 前端 | `npm run build`（由 `beforeBuildCommand` 触发） | `frontend/dist` |
| 5 | 打包 | `cargo tauri build --bundles …` | `tauri/target/release/bundle/**` |

`<triple>` 是 rustc 报的 host triple（如 `x86_64-pc-windows-msvc`）。Tauri 打包时会把这个
后缀去掉，装成主程序旁边的 `ffmpeg(.exe)` / `aivs-backend(.exe)`。

### 图标是画出来的，不是设计稿

仓库里没有源图，而 `tauri build` 缺图标就失败，所以 `make_icons.py` 用纯 Python
（zlib + struct，不要 Pillow、不要 `npx`）画一份：深色圆角底板 + 青色播放三角，取自前端主题的
`--color-base-0` / `--color-accent`。产物**提交进版本库**，打包机不必重跑。
有了设计稿就把 1024px 的图放成 `tauri/icons/source.png`，装上 Pillow 后
`python scripts/make_icons.py --force`。

### sidecar 有三个坑，spec 里各按住一个

Tauri 的 `externalBin` 只认**单个文件**，所以后端必须是 PyInstaller 的 onefile 产物。
`backend/aivs-backend.spec`：

- **alembic 是数据不是代码**。迁移脚本是运行期 exec 的 `.py`，静态分析看不见它们，
  所以 `alembic.ini` 与 `alembic/` 显式进 `datas`，落点必须和
  `migrate.py::_backend_root()` 的算法对得上（冻结后那个位置是 `sys._MEIPASS`）。
  漏了这一条：后端能启动、`/health` 正常，**一建工程就炸**。
- **console 构建 + 不给窗口**。windowed 构建里 PyInstaller 会掐掉 `sys.stderr`，
  Python 的堆栈就进不了 `runtime/backend.stderr.log`，壳只剩一个退出码可报——那是静默失败。
  所以 `console=True`，黑框由壳的 `CREATE_NO_WINDOW` 与 `hide_console` 两处按住。
- **动态导入要 collect**。`uvicorn` 的协议实现、SQLAlchemy 的 sqlite 方言、
  `multipart` 都是运行期才 import 的。

`build_sidecar.py` 打完会**真的启动一次**：等 `endpoint.json` → TCP 探活 → 打一次
`/health` → **建一个空工程**（这一步才跑 alembic）→ 收掉整棵进程树。
「打包成功但跑不起来」要到用户装完双击才暴露，太贵了。

### 单文件产物是两个进程

PyInstaller 的 onefile 是外层 bootloader + 内层真正的 Python。Windows 上
`TerminateProcess` 不牵连子进程，所以 `Supervisor::shutdown` 用 `taskkill /T` 按树杀；
Unix 上 bootloader 会转发 `SIGTERM`，先温和地要求退出（顺带让 uvicorn 走完 lifespan、
把 SQLite 的 WAL 合并回主库），再由 `child.kill()` 兜底。
只 `kill()` 外层的话，里层会变成孤儿——继续占着 `project.db` 与那个回环端口，
而任务管理器里看不到我们的程序。

同一个原因，`START_TIMEOUT` 从 40s 提到 90s：解包几十 MB 再装配 FastAPI，
在冷盘 + 杀软实时扫描的机器上比源码树那条路慢得多。

## 3. 各平台需要什么

| 平台 | 构建期 | 运行期 |
| --- | --- | --- |
| Windows | Rust（MSVC 工具链）、Node 18+、Python 3.11+ | WebView2（Win11 自带，Win10 由安装器引导） |
| Linux | 上面那些 + `libwebkit2gtk-4.1-dev` 等（见下）、`rpm`（只影响 rpm） | WebKitGTK 2.36+（deb/rpm 自动声明依赖；AppImage 用系统那份） |
| macOS | 上面那些 + Xcode 命令行工具 | 无 |

Linux 构建依赖（Debian / Ubuntu）：

```bash
sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev rpm
```

AppImage 打开了 `bundleMediaFramework`：包里带一份 GStreamer 插件。这不是可选项——
分镜板与时间线全靠 `<video>` 预览，宿主机缺编解码器的话画面就是黑的。

## 4. 装完之后

- Windows 的 NSIS 是 `currentUser` 安装：不需要管理员权限，装进 `%LOCALAPPDATA%`。
  安装器带中文与英文两种语言。
- Linux 的 AppImage `chmod +x` 后直接跑；deb / rpm 装进 `/usr/bin` 加桌面项。
- 启动失败**绝不白屏**：壳打开 `boot-error.html`，把 `code / title / detail / suggestions`
  连后端日志的路径一起摆出来（`tauri/src/backend.rs::BootError`）。

## 5. 已知未验证

这台开发机上没有 Rust 工具链，所以第 5 步（`cargo tauri build`）与
`tauri/src/backend.rs` 的改动**没有编译过**。已经在本机验证过的是：图标生成、
sidecar 打包 + 启动 + 建工程自检、体检脚本对缺失工具链的报错。
补上工具链后先跑 `python scripts/build_desktop.py --check`。
