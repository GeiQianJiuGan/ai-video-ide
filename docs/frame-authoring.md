# 镜头制帧与原版制作共存

项目左侧通过「制作方式」切换直出与制帧。制作入口归入「叙事规划」，不再单列「镜头制作」分组；制帧模式中「制作图片」紧接「剧本」，下方为「制帧分镜」。直出模式显示「直出分镜」。队列细看通过底部任务控制台进入，批量编排从直出分镜页进入。

制作方式按项目记在本机。直出与制帧复用同一分镜板、泳道、镜头属性、预览与版本采纳界面，只切换视频输入：直出引用角色、场景、道具设定；制帧引用「制作图片」中已采用的帧图，并读取独立的视频描述。制帧单镜与整幕、批量生成都走帧图入口，缺少帧图或提示词时报告具体镜头的错误，不回退到直出。切换制作方式前保存制帧视频草稿，保存失败则保留当前模式。两种流程共用幕、镜头和最终视频版本列表，历史版本保留。

已有镜头可在「制作图片」点击「AI 规划本镜画面」，先审阅再采用；无需重建完整剧本。逐帧故事、图片提示词和候选制作集中在这页。已有空白画面按原顺序与名称填入，保留画面 ID。含剧情、提示词、参考图、候选或任务的草稿不被新计划覆盖；采用时再次检查镜头修改时间和画面位置。也可完全手动填写。规划本身不提交图片或视频生成。

## 制作步骤

1. 在剧本或分镜中创建幕和镜头。也可切到制帧模式后使用 AI「制作完整分镜」，先审阅逐帧故事、图片提示词和视频提示词，再采用计划。
2. 进入「制作图片」，选择镜头，添加任意数量的画面位置，如开场、动作、收尾。画面位置与同一位置的候选版本分别管理。
3. 填写画面的叙事位置、对应剧情和静态图片提示词，按「角色 / 场景 / 道具」选择已有实体的当前设定图。选中的参考图按添加顺序排列，可前移、后移或移除。也可上传画面或从项目素材添加候选图片。
4. 图片生成按当前图片 API 声明的模型容量或工作流的实际图片参考槽位数，采用列表前面的图片并舍弃超出的尾部。界面提前标明舍弃项，预检与任务记录实际采用和舍弃的清单。原选择与资产保留，未声明数量限制的自定义 API 不臆造上限。对比候选并明确采用，也可将预览图追加为参考继续修改。
5. 在「制帧分镜」同一个分镜板的右侧输入面板选择首帧及可选尾帧，填写视频动作、运镜、对白与声音。需要时选择独立的视频预设。
6. 点击「检查实际输入」，核对真实提交的图片。其他画面不会被自动提交为中间关键帧，人物设定图也不进入该视频请求。
7. 在共用分镜板预览并采用新视频版本；生成完成不会自动替换当前采用的视频。

草稿在切换镜头、画面和离开工作空间前保存；也可手动保存。图片与视频任务共用既有任务队列，支持暂停、取消和重试。批量生成只处理有描述、未选图且无未完成图片任务的画面；逐项展示入队失败。

## 数据与隔离

- schema 25 增加 `frame_workspace`、`frame_card`、`frame_candidate`，升级使用既有工程迁移和备份流程。旧 Shot 行无需改写。
- schema 27 为帧卡增加对应剧情 `story` 和叙事位置 `role`；它们供规划与制帧审阅，视频实际输入仍由选定首尾帧决定。
- 制帧草稿不写 Shot 的 prompt、intent、首尾帧、上游依赖、seed 或制作状态。原版的首尾帧候选生成仍使用原规则。
- 新增 `shot_frame` 图片模板，不使用要求「无人物」的场景模板。原有三个素材模板保持原内容。
- 图片候选追加保存生成参数与参考资产清单，生成完成不自动选图。移除画面保留图片文件；存在未完成图片任务时应先取消任务。
- 视频任务以 `creation_pipeline=frames` 标识，冻结实际帧资产、画面来源、独立视频描述、时长及解析后的路由。执行不读取当前采用帧、不带入旧素材上下文、不沿用旧导演意图和上游末帧。
- 新旧视频使用同一 GenerationVersion 表；新流程产物只追加候选，原版自动采用逻辑保持原行为。明确采用新版本是影响成片的操作。
- 首帧必须对应真正的首帧入口；首尾帧必须都能绑定。缺少入口时入队前报错，不把首帧降级为普通参考图。

## 接口

- `GET/POST /projects/{pid}/shots/{sid}/frames`：读取工作空间 / 添加画面。
- `PATCH/DELETE /projects/{pid}/frame-cards/{cid}`：编辑 / 移除画面。
- `POST /projects/{pid}/frame-cards/{cid}/candidates`：添加项目图片候选。
- `POST /projects/{pid}/frame-cards/{cid}/adopt`：采用指定候选。
- `POST /projects/{pid}/frame-cards/{cid}/generate`：按已保存的画面描述及设定图生成候选。
- `PUT /projects/{pid}/shots/{sid}/frame-video`：保存独立视频草稿。
- `POST /projects/{pid}/shots/{sid}/frame-plan/propose`：按现有镜头生成只读的待审阅制帧计划。
- `POST /projects/{pid}/shots/{sid}/frame-plan/apply`：校验原镜头与画面位置后，原子采用逐帧计划。
- `POST /projects/{pid}/shots/{sid}/frame-video/plan`：只读预检及实际输入清单。
- `POST /projects/{pid}/shots/{sid}/frame-video/generate`：冻结输入并提交视频任务。
- `GET /projects/{pid}/frame-capabilities`：当前调用方式与可选首帧预设。
- `GET /projects/{pid}/frame-reference-materials`：按角色 / 场景 / 道具列出当前设定图，以及图片服务的参考容量。

图片 API 的已知模型上限在适配层维护，依据 [OpenAI Images edit 合同](https://developers.openai.com/api/reference/resources/images/methods/edit) 和 [Gemini 图片生成文档](https://ai.google.dev/gemini-api/docs/image-generation)。工作流容量直接读取实际 `AIVS_REF_*` 图片入口，不将首尾帧入口计为设定参考槽位。

图片数量少于工作流槽位时，未使用的媒体入口及相关连线与专属中间节点从本次提交图中摘除，不保留工作流保存时的示例图片；种子、宽高等标量默认值保持原样。处理与视频共用同一套摘除及必填输入修复逻辑，原始预设文件不变。

手动画面数量不限，AI 完整分镜每镜最多规划八张，视频执行支持单首帧与首尾帧。AI 画面规划在完整分镜任务中提供；自动多段视频编排、局部重绘工具和相邻镜头连续性自动审查尚未实现，可创建多个镜头并使用既有时间线装配。

## 验证

隔离回归覆盖草稿持久化、跨镜头拒绝、候选追加、原槽位不变、冻结帧不随改选变化、视频不自动采用、制帧模板支持人物、参考图能力拦截、独立视频预设及严格首帧入口、移除画面后保留素材。旧路由、首尾帧、抽帧、图片及工程迁移测试继续执行。

本地浏览器验收使用独立临时工程与合成测试图片，不代表真实模型生成质量，未调用付费生成服务。

## 制帧视频提示词优化

视频输入面板提供「按镜头 Skill 优化」：根据选定画面的剧情、静态描述、当前动作草稿及时长生成待审阅提示词，点击采用后才写入草稿。H3 使用三字段正文，首尾帧时间对齐由程序补齐；默认连续单镜，明确切镜才增加 Shot 和切换时间。图片描述不等于视觉识别，生成质量仍需真实模型验收。

「检查输入与提示词」提供提交预览。Picture 1/2 是草稿中的首尾帧槽位，执行时根据实际工作流图册重新绑定；预览编号可能随实际接线顺序变化。修改草稿或选图会清除旧预览。ComfyUI 与 REST 的制帧提交均使用工程选定的视频渲染规范，历史直出流程继续保留原路径。

新增 `POST /projects/{pid}/shots/{sid}/frame-video/optimize`，接收视频草稿，返回 `{prompt}`，不落库；plan 响应增加 `prompt_preview`。

## 制帧工作区交互

画面条显示待编写、待生成、制作中、待审阅、已采用状态，镜头标题显示采用进度。生成新候选为主要操作，导入图片与画面管理按需展开；窄窗口改为上下排列。请求期间禁用编辑区域，避免提交时改动草稿。

批量补图只处理有提示词、无候选、未采用且没有在途任务的画面；已有候选可审阅采用，或单独生成新候选。候选首次完成后自动显示预览。保存后同步本地画面内容，并丢弃过期轮询响应，避免切换画面时恢复旧内容。视频提示词优化前先保存最新画面剧情。

## 计划画面与实际成片衔接

开场帧卡标为「计划开场」，尾帧卡标为「预期收尾」。先制作并采用画面，生成并审阅采用视频，再根据实际成片衔接下一镜；上游未完成时不能用预期收尾冒充实际结束画面。

在目标画面的「承接已采用的视频画面」中选择来源镜头。连续动作选择 opening，抽帧追加为候选，审阅采用后自动绑定为本镜头开场，并保留已有视频动作草稿；换机位选择 reference，实际画面排在图片参考列表首位，随后按下一镜剧情重新生成图片。换场景可以独立制作。默认从已采用版本的有效结束位置抽取，支持指定源视频绝对秒数；指定位置时须在剪辑中同步裁剪上游，本操作不修改视频或时间线。

候选冻结来源镜头、版本、资产、取帧位置与用途。来源改选后提示过期，禁止采用旧衔接候选或用它提交新视频；已有视频版本保留。视频入队参数记录所用候选来源。引用源片受到普通资产删除保护，强制删除仍可能造成素材缺失。

`POST /projects/{pid}/frame-cards/{cid}/continuity` 接收 `{source_version_id, at: "end" | number, use: "opening" | "reference"}`，返回新增候选、抽帧资产与来源信息。

AI 工具：`get_frame_workspace` 返回已采用版本、视频版本、任务及候选来源；`extract_frame_continuity` 提出抽帧操作；`update_frame_video` 修改独立视频草稿；`generate_frame_video` 提交已保存草稿。写工具仍按现有提案审阅/免确认设置执行，不绕过采用流程。任务入队并不意味着生成完成，必须读取任务结果并审阅采用后才进入下游。草稿在提案后变化时拒绝覆盖。

普通聊天增加可选 `production_mode: direct | frames`，公共页面也传入当前制作方式；不传的旧客户端保留页面 scope 行为。
