# 镜头制帧与原版制作共存

项目左侧通过「制作方式」切换两组菜单：直出（直接制作）显示幕流程与镜头编辑器；制帧（制帧制作）显示镜头制帧与视频生成。概览、设定素材、剧本分镜、时间线与资产为共用入口。队列细看通过底部任务控制台进入。

菜单偏好按项目记在本机，首次默认直出；直接打开某个工作空间时自动显示对应菜单。切换时先等待当前页面保存草稿，保存失败则保留当前菜单。两种流程共用幕、镜头和最终视频版本列表，可以在同一项目内混用；菜单切换不修改任何生成参数。

## 制作步骤

1. 在剧本或分镜中创建幕和镜头。
2. 进入「镜头制帧」，选择镜头，添加任意数量的画面位置，如开场、动作、收尾。画面位置与同一位置的候选版本分别管理。
3. 填写具体画面描述，选择人物、场景、道具等设定参考图，再生成候选。也可上传画面或从项目素材添加图片。
4. 对比候选并明确采用。可以将预览图加入参考列表，继续生成修改版。图片服务必须支持所选参考输入；不允许静默跳过设定图。
5. 在「视频生成」中选择首帧及可选尾帧，单独填写动作、运镜、对白与声音。需要时可为制帧流程选择独立的视频预设，不改项目默认预设。
6. 点击「检查实际输入」，核对真实提交的图片。其他画面不会被自动提交为中间关键帧，人物设定图也不进入该视频请求。
7. 生成视频候选后，在原镜头编辑器预览并明确采用。新流程不自动改变该镜头已采用的视频。

草稿在切换镜头、画面和离开工作空间前保存；也可手动保存。图片与视频任务共用既有任务队列，支持暂停、取消和重试。批量生成只处理有描述、未选图且无未完成图片任务的画面；逐项展示入队失败。

## 数据与隔离

- schema 25 增加 `frame_workspace`、`frame_card`、`frame_candidate`，升级使用既有工程迁移和备份流程。旧 Shot 行无需改写。
- 制帧草稿不写 Shot 的 prompt、intent、首尾帧、上游依赖、seed 或制作状态。原版的首尾帧候选生成仍使用原规则。
- 新增 `shot_frame` 图片模板，不使用要求「无人物」的场景模板。原有三个素材模板保持原内容。
- 图片候选追加保存生成参数与参考资产清单，生成完成不自动选图。移除画面保留图片文件；存在未完成图片任务时应先取消任务。
- 视频任务以 `creation_pipeline=frames` 标识，冻结实际帧资产、画面来源、独立视频描述、时长及解析后的路由。执行不读取当前采用帧、不带入旧素材上下文、不沿用旧导演意图和上游末帧。
- 新旧视频使用同一 GenerationVersion 表；新流程产物只追加候选，原版自动采用逻辑保持原行为。明确采用新版本是影响成片的操作。
- 首帧必须对应真正的首帧入口；首尾帧必须都能绑定。缺少入口时入队前报错，不把首帧降级为普通参考图。

## 接口

- `GET/POST /projects/{pid}/shots/{sid}/frames`：读取工作空间 / 添加画面。
- `PATCH/DELETE /projects/{pid}/frame-cards/{cid}`：编辑 / 移除画面。
- `POST /projects/{pid}/frame-cards/{cid}/candidates`：添加项目图片候选。
- `POST /projects/{pid}/frame-cards/{cid}/adopt`：采用指定候选。
- `POST /projects/{pid}/frame-cards/{cid}/generate`：按已保存的画面描述及设定图生成候选。
- `PUT /projects/{pid}/shots/{sid}/frame-video`：保存独立视频草稿。
- `POST /projects/{pid}/shots/{sid}/frame-video/plan`：只读预检及实际输入清单。
- `POST /projects/{pid}/shots/{sid}/frame-video/generate`：冻结输入并提交视频任务。
- `GET /projects/{pid}/frame-capabilities`：当前调用方式与可选首帧预设。

首版允许设计任意数量的画面，视频执行支持单首帧与首尾帧。自动多段视频编排、AI 自动规划画面、局部重绘工具和相邻镜头连续性自动审查尚未实现；可手动创建多个镜头并使用既有时间线装配。

## 验证

隔离回归覆盖草稿持久化、跨镜头拒绝、候选追加、原槽位不变、冻结帧不随改选变化、视频不自动采用、制帧模板支持人物、参考图能力拦截、独立视频预设及严格首帧入口、移除画面后保留素材。旧路由、首尾帧、抽帧、图片及工程迁移测试继续执行。

本地浏览器验收使用独立临时工程与合成测试图片，不代表真实模型生成质量，未调用付费生成服务。
