# 05 · 生成方式与节点要求

本文回答一个问题：**要让 aivs 真的出片，模型端到底得准备什么。**

本工具自己不做推理，视频一定由外部服务出。**本工具不维护模型端的图**——lora、加速节点、
采样器怎么摆是模型端自己的事，我们只按约定往几个入口里填值。

代码真源：[`app/generation/providers/`](../backend/app/generation/providers/)。
本文和代码不一致时以代码为准，改了代码请同步这里。

## 0. 三种调用方式

在设置页选（应用级设置 `video.provider`，默认 `comfy_preset`，见
`app/core/config.py:54`）。注册表在 `providers/registry.py:19`。

| 方式 | 需要什么 | 要不要工作流 | 状态 |
| --- | --- | --- | --- |
| `comfy_preset` | 一个能连上的 ComfyUI + 一份**预设**（API 格式 json） | 要，但只认标题约定 | 默认核心路径 |
| `http_api` | 一个实现了本工具 REST 合同的服务地址 | **不要** | 平级可选 |
| `comfy_workflow` | 工程里导入并校验过的 Workflow + 绑定表 | 要，且要逐字段绑定 | 兼容，不再演进 |

`comfy_workflow` 不实现 `VideoProvider`，`registry.provider()` 会直接挡下来并说明怎么走
（`registry.py:52`）；它只在「设置里选了它 **且** 这个任务确实绑了工作流」时才跑
（`services/generation.py:375`）。

## 1. 本轮只有 R2V，两种模式

`providers/base.py:24` 定义 `MODES = ("i2v", "flf")`：

| 模式 | 何时用 | 入参 |
| --- | --- | --- |
| `i2v` | 只有首帧 | 首帧 + 参考素材 + prompt |
| `flf` | 首尾帧都有（转场、单线程续接） | 首帧 + 末帧 + 参考素材 + prompt |

模式不是用户选的，由「有没有末帧」自动定（`services/generation.py:402`）。
**没有 T2V**：没有首帧的镜头在真正要跑的时候报 `MISSING_INPUT`「这个镜头还没有首帧」，
建议里给「挑一张首帧」或「把上一幕的衔接改成续接末帧」两条出路——而不是生成一段跑偏的画面。
转场那条边缺首帧图的话，`POST /sequence/plan` 的账单里就会先标出来。

**首尾帧与参考素材是两件事**（`base.py` 的 `RefAsset`）：首尾帧决定「画面从哪一格开始 /
结束」，参考素材决定「谁出场、在哪儿、动作什么样、跟着哪段声音」。两种模式都带参考素材。

这条分界在数据上也是分开的，**不靠优先级猜**：首 / 末帧是镜头上那两个显式槽位
（`Shot.first_frame_asset_id` / `last_frame_asset_id`，schema 13 / 迁移 `0013_shot_frames`），
只能是图片（模型端那两个入口接的是 LoadImage，挑了视频 / 音频报 422「首帧只能是图片」），
**清空要传 `''`**（PATCH 的 `null` 会被 `exclude_none` 吃掉）。挂角色、选地点变体只是**往账单里
加参考素材**——一条都不会被提拔成画面第一格。历史上 `_assign_roles` 会把优先级最高的那条
（通常是角色三视图）标成 `first_frame` 并真的喂进 `AIVS_FIRST_FRAME`，那是「默认首张就是首帧」
这个 bug 的来源，现在没有任何路径能悄悄提拔一条参考素材。

**参考素材分三种媒体**（`RefAsset.media` = `image` / `video` / `audio`，由文件后缀判定，
走 `assets.kind_of_suffix`，不是用户手填），各进各自的槽位族。认不出后缀的进账单但不采用，
`reason` 里写清原因。

## 2. comfy_preset：全部要求就是几个节点标题

约定在 `providers/presets.py:42`。做法只有一条：

> 在 ComfyUI 里右键入口节点 → **Title**，改成下面的名字，然后用
> **Save (API Format)** 导出 json，在设置页上传成一份预设。

**不是要求入参名和本项目一致**——节点内部的字段名不用改。我们按标题找到节点后，在它的
`inputs` 里按一串候选字段名取**第一个命中的**填进去，所以 LoadImage / CLIPTextEncode /
各家原生节点都能覆盖，我们不需要认识它的 `class_type`。

| 节点标题 | 填什么 | 会往哪个字段填（按顺序取第一个存在的） | 必需性 |
| --- | --- | --- | --- |
| `AIVS_PROMPT` | 正向提示词 | `text` / `prompt` / `string` / `value` | **必需（唯一必需项）** |
| `AIVS_FIRST_FRAME` | 首帧图（文件名） | `image` / `filename` / `url` / `value` | 可选；没有它时首帧当参考图 1 送进去 |
| `AIVS_LAST_FRAME` | 末帧图（文件名） | `image` / `filename` / `url` / `value` | 做转场 / 续接必需 |
| `AIVS_REF_1` … `AIVS_REF_9` | **参考图**：角色表 / 地点参考图 / 道具参考图（文件名） | `image` / `filename` / `url` / `value` | 强烈建议，否则丢人物形象 |
| `AIVS_REF_VIDEO_1` … `AIVS_REF_VIDEO_4` | **参考视频**：动作 / 运镜参考那一段（文件名） | `video` / `file` / `filename` / `path` / `url` / `value` | 可选；接 VHS / LoadVideo 那类节点 |
| `AIVS_REF_AUDIO_1` … `AIVS_REF_AUDIO_4` | **参考音频**：对白 / 口型要跟的那一段（文件名） | `audio` / `file` / `filename` / `path` / `url` / `value` | 可选；接 LoadAudio 那类节点 |
| `AIVS_NEGATIVE` | 负向提示词 | `text` / `prompt` / `string` / `value` | 可选 |
| `AIVS_DURATION` | 时长（**秒**，float） | `length` / `duration` / `frames` / `seconds` / `num_frames` / `value` | 可选 |
| `AIVS_SEED` | 种子（int） | `seed` / `noise_seed` / `value` | 可选 |

必需项只剩一个（`presets.py` 的 `REQUIRED`）：`AIVS_PROMPT`。分工是**首尾帧那类模型补转场、
R2V 出正片**，而多参考图的 R2V 图常常一个首尾帧入口都没有——为此拒绝存图等于把这类模型
整个挡在外面，所以「没有 `AIVS_FIRST_FRAME` / `AIVS_LAST_FRAME`」不再是体检不过。
它只影响两件事，且**都不静默**：

- `flf_ready = false`（列表里没有 FL2VA 徽标）——补转场要的是严格首尾帧，这份图做不了，
  项目里把它选成 FL2VA 角色会报 `INVALID_WORKFLOW`「预设不可用」；
- 生成时**首帧当参考图 1** 送进去（`comfy_preset._refs` 里插队），并写一条
  `req.notes` 冻结进版本参数 `ref_notes`，界面上看得见。

**其余入口缺了也不算错**——那一项就沿用图里原来的值（`comfy_preset.py` 显式跳过空值，
不会用空串把它冲掉）。参考图槽位上限 9 个、参考视频 / 参考音频各 4 个
（`presets.py` 的 `REF_SLOTS` / `REF_VIDEO_SLOTS` / `REF_AUDIO_SLOTS`），
**图里标了几个就用几个，不必凑满，中间跳号也不算错**。

### 人物图 / 地点图 / 动作视频 / 对白音频从哪进去？——`AIVS_REF_*` 三族

素材进模型的口子有两类：**首尾帧**（`AIVS_FIRST_FRAME` / `AIVS_LAST_FRAME`，各一张图）与
**参考素材**（想喂几个标几个）。角色表、地点参考图、道具参考图、动作参考视频、对白音频
走的都是后者，且**按媒体分族**：

| 媒体 | 槽位族 | 上限 | 模型端那头通常是 |
| --- | --- | --- | --- |
| `image` | `AIVS_REF_1…9` | 9 | LoadImage 那类 |
| `video` | `AIVS_REF_VIDEO_1…4` | 4 | VHS_LoadVideoPath / LoadVideo 那类 |
| `audio` | `AIVS_REF_AUDIO_1…4` | 4 | LoadAudio 那类 |

**三族绝不混着数**（唯一那张表是 `presets.REF_MARKERS_BY_MEDIA`）：混着数的话「图多音频少」
会被算成装得下，然后那段音频被安静丢掉；把一段 `.mp4` 填进 `AIVS_REF_1` 更糟——它进的是
LoadImage，既不报错也出不了片。

上下文账单（`services/context.py`）把候选**排成一张清单**，按优先级排序：

| kind | 优先级 | 来源 |
| --- | --- | --- |
| `first_frame` / `last_frame` | — | 镜头上那两个显式槽位（不占参考槽位） |
| `manual` | 110 | 上下文检查器里手动添加的素材（图 / 视频 / 音频都收） |
| `character_sheet` | 100 | 出场形象的当前角色表（镜头没挂人物时继承幕级人物节点） |
| `location_reference` | 90 | 本幕主地点变体的参考图（幕里另外选的地点 85） |
| `prev_frame` | 80 | 上游镜头**抽出来的真末帧** |
| `prop_reference` | 60 | 出场道具的当前参考图 |

**账单不再截断**（`context.ref_capacity`）。以前这里卡一个应用级上限 `video.ref_limit`（默认 8），
但那个数字和模型端那份图真标了几个 `AIVS_REF_*` 是两回事，配错一边就白丢用户的角色图。
现在上限**由适配器回答**（`base.RefCapacity`，带 `source` / `detail` 说明这个数字哪来的：
预设名 / 「REST 合同」；通用 REST 合同与「还没选预设」都是不限数量），采用的照样全采用，
超出槽位的部分变成生成前的一次确认（见下）。整份账单冻结进 `GenerationVersion.context_json`。

采用的每一条带一个 `role`，由 `_assign_roles`（`context.py`）标，**顺序只有两级**：

1. 镜头上那两个显式槽位（`first_frame` / `last_frame` 两条 kind）→ 对应的 role；
2. 首帧没指定、而这个镜头要续接上游（`tail_frame` 衔接）→ `prev_frame` 那张当 `first_frame`；
3. **到此为止**：两个都没有就是这个镜头没有首帧。其余采用条目一律 `reference`。

**绝不把优先级最高的参考素材提拔成首帧。** 以前第 2 步之后还有一条「否则拿优先级最高的那张」，
于是界面上给一张角色三视图标了「首帧」，模型端也真把它当画面第一格用。这条规则只写在
`context.py` 一处，`services/generation.py::_images_of` 照账单读 `role`，不自己再挑一遍。

参考素材按账单顺序**在各自族内**填进 `AIVS_REF_n` / `AIVS_REF_VIDEO_n` / `AIVS_REF_AUDIO_n`
（`comfy_preset.py::_refs`），**槽位不够只降级、不失败**：

- 图里 3 个图片槽位、账单给了 5 张图 → 填前 3 张，把「这几个没喂进去：…」写进 `req.notes`；
- 某一族**一个槽位都没有** → 那一族整族喂不进去，照样提交，但留一条 note 说明
  （图片那族的说法是「参考图没喂进去，人物形象只能靠首帧带」）——这正是形象跑偏的现场；
- 这些 note 与「实际喂了哪几个」一起冻结进版本参数（`params.ref_notes` / `params.refs`），
  场景工作台与镜头编辑器的版本卡上直接显示「参考素材 N 个」+ 降级说明。

**装不下是一次确认，不是失败**：入队前后端先回 `REF_OVER_CAPACITY`，说清每一族采用了几个、
只能喂几个、会丢哪几个（**此时一个任务都没入队**，批量路径是先扫完再动手），用户看清之后带
`allow_ref_drop=true` 重来一次同一个入口。账单里那条 `capacity` 顶层几个键说的是**参考图**
（历史口径），视频 / 音频看 `capacity.media.{image|video|audio}`，顶层 `over` = 任意一族装不下。

ComfyUI 那类图**只按顺序收素材、收不到标签**，所以默认会在 prompt 末尾附一句
「参考素材说明：参考图1=林小雨（常服）（褪色军绿夹克，短发）；参考图2=雨夜巷口。参考音频1=林小雨台词。」
（`base.py` 的 `ref_hint`，一句话写完，序号**按媒体各自从 1 数**——槽位就是按媒体分开的），
让模型对得上号。括号里那一段是**素材描述**（`Asset.description`，用户手填或 AI 看图补的
那一句）：这是模型引用一个素材时唯一看得到的说明，没写就不出现这个括号，
**此时整句与加这一列之前逐字相同**。它进 prompt 之前只过一道 `clip_desc`
（压掉换行 + 超过 `DESC_MAX = 120` 截断）——**全链路只有这一处截断**，账单与冻结的版本参数里
存的都是全文。不想要这一句就把设置里的 `video.ref_labels` 关掉（`config.py`）——关掉之后
素材照旧喂，只是不附说明。

账单里的人物名 / 地点名**不会自动拼进 prompt 正文**（prompt 只取
`shot.prompt or shot.description or scene.prompt`），拼进去的只有上面那句参考素材说明。

### 除了标题，图本身还有两条硬要求

1. **顶层必须是 API 格式**：`{节点id: {class_type, inputs}}`。界面工作流（带 `nodes` 数组
   那种）会在 `parse_graph` 就被拒，报 `INVALID_WORKFLOW`「不是 ComfyUI 的 API 格式」。
2. **末端必须有保存节点**（SaveImage / VHS / 任何会写 `outputs` 的节点）。我们从
   `history.outputs` 里认 `images` / `gifs` / `videos` / `files` 四个键，取**最后一个**产物
   （`comfy/client.py:156`）。跑完了没产物 → `poll()` 判 failed，`fetch()` 报
   `WORKFLOW_ERROR`「ComfyUI 没有产出任何文件」。

### 什么时候检查、报什么错

| 时机 | 检查什么 | 不过关时 |
| --- | --- | --- |
| 上传预设（`POST /settings/presets`） | 是否 API 格式；`AIVS_PROMPT` 在不在；标题贴的节点有没有可填字段 | `INVALID_WORKFLOW`，**不落盘**（`presets.save`） |
| 上传 / 列出预设 | 三族各有几个槽位（`ref_slots` / `ref_video_slots` / `ref_audio_slots` / `ref_slots_by_media` / `ref_hint`）；首尾帧入口在不在（`first_frame_ok` / `flf_ready` / `r2v_ready`） | 都不拦：0 槽也算 `ready`，一个首尾帧入口都没有也算 `ready`；设置页把「参考图 0 槽」标成警告、没有 FL2VA 徽标。参考视频 / 参考音频 0 槽是常态，只在大于 0 时画徽标 |
| 项目里选预设（`PUT /projects/{pid}/preset`） | R2V 角色看 `r2v_ready`、FL2VA 角色看 `flf_ready` | `INVALID_WORKFLOW`「预设不可用」，建议里按角色说清缺什么 |
| 设置页「测试连接」（`POST /settings/probe`） | ComfyUI 通不通；默认预设存不存在、`ready` 与否 | `COMFY_OFFLINE` / `NOT_FOUND` |
| 入队前（`generation` 扫账单） | 每一族采用了几个 vs 槽位有几个 | `REF_OVER_CAPACITY`：**一个任务都不入队**，说清每族会丢哪几个，等 `allow_ref_drop=true` 再来一次 |
| 真正提交时（`submit`） | 有没有选默认预设；要用末帧但图里没有 `AIVS_LAST_FRAME` | `MISSING_CAPABILITY` / `INVALID_WORKFLOW`「这份预设不支持首尾帧」 |
| 真正提交时（`_refs`） | 各族素材数 vs 该族槽位数；有没有 `AIVS_FIRST_FRAME` | **不报错**，按族降级（首帧改走参考图 1）并把这件事写进 `params.ref_notes` |

注意这两个缺口，它们都不是错，但都要知道：**只有 `AIVS_PROMPT` 的预设上传时就是 `ready`**，
做 R2V 正片没问题，但一到转场 / 续接才会报「这份预设不支持首尾帧」——要做衔接的话，
在上传时就自己确认图里有 `AIVS_LAST_FRAME`（或者在项目里给 FL2VA 角色另选一份预设）。
**没有 `AIVS_REF_*` 也照样 `ready`**——它跑得起来，只是人物形象只能靠首帧带，
预设列表里那行会把这句话写出来。参考视频 / 参考音频**一个槽位都没标是常态**，
所以列表上不给它们画「0 槽」警告——那样只会把「参考图 0 槽」这个真问题埋掉。

### 最常见的上传失败：传的是界面工作流

`user/default/workflows/` 里存的、界面上「保存」出来的，都是**界面格式**，顶层是
`{id, revision, last_node_id, last_link_id, nodes: [...], links: [...]}`。
API 格式的顶层直接是「节点 id → `{class_type, inputs}`」，没有 `nodes` / `links`。

传错了会报 `INVALID_WORKFLOW`「这是界面工作流，不是 API 格式」
（`services/workflows.py::parse_graph` 专门认这一种，否则那串顶层键会被当成节点名列出来，
看着像是节点坏了）。换导出方式就行，**节点标题不用重设**：

- 当前前端：菜单「工作流 / Workflow」→「导出 (API) / Export (API)」；
- 旧版前端：设置里打开「Enable Dev mode Options」，界面上才会出现「Save (API Format)」。

### 七个坑（都来自「我们只填值、不解释」这个设计）

- **`AIVS_DURATION` 填的是秒，不是帧**。候选字段里有 `frames` / `num_frames` / `length`，
  但我们**不做 fps 换算**（`comfy_preset.py:101` 直接传 `req.duration`）。如果你的节点要帧数，
  别把标题贴在它上面——贴在真正吃秒数的那个输入上，或者干脆不贴，用图里写死的值。
- **`AIVS_SEED` 不填就是图里那个固定值**。镜头没设 seed 时我们跳过这一项，于是同一个镜头
  重跑会出一样的画面。想要每次不同就在镜头上填 seed。
- **标题重复只有第一个生效**。`entry_points` 按标题去重（`presets.py:90`），
  两个节点都叫 `AIVS_PROMPT` 时，后一个被静默忽略。正向和负向必须是两个不同标题；
  参考素材也别把两个节点都标成 `AIVS_REF_1`——那样只有一个进得去。
- **参考素材槽位要贴在真正能多收一个的节点上**，且**别跨族贴**。我们只管把文件名填进
  `AIVS_REF_n` / `AIVS_REF_VIDEO_n` / `AIVS_REF_AUDIO_n`，**不改图的连线**：那个 LoadImage /
  LoadVideo / LoadAudio 的输出得真的接到模型对应的入口上，否则图里多了一个没人用的加载节点，
  画面一点变化都没有。把 `AIVS_REF_1` 贴在 LoadVideo 上更糟——我们会把一张 `.png` 的文件名
  填给它，那既不报错也出不了片。喂了几个、有没有被截断，看版本卡上那几行说明。
- **连线输入会被覆盖成标量，图就跑坏了**。标题必须贴在那个字段是**标量**的节点上。
  我们只看「候选字段名在不在 `inputs` 里」，不看它当前是常量还是 `[node_id, index]` 连线
  （`presets.py:93`）——所以标题请贴在 LoadImage / CLIPTextEncode 这类真正的输入端节点上，
  不要贴在中间的采样器或任何靠连线拿值的节点上。
- **素材是先上传再按文件名引用的**，**三种媒体都走 `/upload/image`**。我们把首/末帧与每一个
  参考素材（图 / 视频 / 音频）POST 到 ComfyUI 的 `/upload/image`（子目录 `aivs`），拿回文件名再
  填进去。那个端点名字里带 image，但它收的是任意 input 文件——ComfyUI 自己的前端传视频
  给 VHS 时也是打它（`comfy/client.py::upload_input`，所以那个方法刻意不叫 `upload_image`）。
  ComfyUI 版本必须支持 `/upload/image`，且不能是只读部署。
- **预设不是工程数据**。存在 `runtime_dir/presets/<名字>.json`，属于「我这台机器怎么调
  模型」，不进 `project.db`，换工程不用重新上传，换机器要重新上传。

### ComfyUI 侧要开放的 HTTP 端点

`app/generation/comfy/client.py`：

| 端点 | 用途 | 缺了会怎样 |
| --- | --- | --- |
| `GET /system_stats` | ping / 「测试连接」 | 一律判 `COMFY_OFFLINE` |
| `POST /prompt` | 提交 | 无法生成 |
| `POST /upload/image` | 传首/末帧与全部参考素材（图 / 视频 / 音频都走它） | 无法生成（报错里点名这个端点） |
| `GET /history/{id}` | 轮询 + 取产物清单 | 会一直等到超时 |
| `GET /view` | 下载产物 | 出片了但拿不回来 |
| `GET /object_info` | 只有旧 `comfy_workflow` 路径的节点探测用 | 不影响 preset 路径 |

## 3. 按场合看：这一幕 / 这条衔接需要哪些入口

三种衔接模式（`SceneLink.mode`，`services/sequence.py:51`）对模型端的要求不一样：

| 场合 | 生成模式 | 预设需要的入口 | 备注 |
| --- | --- | --- | --- |
| 单幕镜头（有首帧） | `i2v` | `AIVS_PROMPT`（有 `AIVS_FIRST_FRAME` 更好） | 没有首帧入口时那张首帧改走参考图 1，并写一条 note |
| 想让人物 / 地点形象稳住 | `i2v` / `flf` | 再加 `AIVS_REF_1…n` | 不加也跑，但形象只能靠首帧带 |
| 想让动作 / 运镜跟一段样片 | `i2v` / `flf` | 再加 `AIVS_REF_VIDEO_1…n` | 图里得真有能收视频的加载节点，否则整族喂不进去（有 note） |
| 想让口型 / 节奏跟一段声音 | `i2v` / `flf` | 再加 `AIVS_REF_AUDIO_1…n` | 同上；两族都是可选的，0 槽是常态 |
| 衔接 = `cut`（硬切） | 不生成 | —— | 一条边一个东西都不产 |
| 衔接 = `transition`（转场） | `flf` | 必须同时有 `AIVS_FIRST_FRAME` + `AIVS_LAST_FRAME` | 首帧 = 上一幕**真末帧**，末帧 = 下一幕首镜头的真首帧；**两侧都出片了才补得出来** |
| 衔接 = `tail_frame`（续接末帧） | `i2v` | 最低配置就够 | 只是把上一幕末帧当下游首帧，不产转场 |
| 编排 `sequential` 模式 | `i2v` | 最低配置就够 | 全链条按末帧续接，图上的 `transition` 边被**忽略**（账单里会写出来） |

**转场是补的，不是同一轮做的**：门槛在 `services/story.py::footage_blocker`（两级共用一条），
接缝两侧的镜头都有成片才补——上游没出片就没有真末帧、下游没出片就没有真首帧，
补一段两头都对不上的过渡只会让接缝更明显。所以新工程第一次 `POST /sequence/run` 一段转场都
不会补（账单的 `notes` 会说出来），等这一轮镜头出片后在分镜页按一次「一键生成转场」就补上；
分镜板上那个按钮能不能点看连接器的 `can_generate`，不能点的原因在 `blocked`。

转场的实现细节：它落成一个 `Shot.kind="transition"` 的镜头，属于上一幕并排在最后，于是
`timeline.auto_assemble` 的「scene.index_no + shot.index_no」排序天然把它放到两幕之间，
导出侧一行不用改。时长默认 1.5s，允许范围 `TRANSITION_RANGE = (0.5, 4.0)`
（`sequence.py:56`）；已经出片的转场不会重做（硬约束 3：版本永不覆盖）。

**上一幕的「真末帧」是 FFmpeg 抽出来的一张 PNG，不是那段视频**（`services/frames.py`，
`-sseof` 抽帧 → 登记 `Asset(kind="frame")` → 同 (asset, at) 幂等复用）。这一步不经过任何
生成节点，抽帧失败报 `FFMPEG_ERROR`，建议里会给「改用转场衔接」这条出路。
这张帧是**临时资源**：落 `cache/frames/`、不进资产总账也不算孤儿，源成片一删就跟着删——
它随时能重抽，没必要让用户在资产库里对着一堆自己没导入过的图猜哪张能删。

## 4. http_api：一个节点都不需要

不用 ComfyUI 也能接。合同固定四个端点（`providers/http_api.py:40`），服务端实现就行：

```
POST {base}/submit
  body {mode, prompt, negative, duration, seed, client_id, extra,
        first_frame, first_frame_name, last_frame, last_frame_name, refs}
  —— 两个 frame 是 base64（图在我们这边，不能指望对方能读我们的磁盘）
  —— refs 是**首尾帧之外的参考素材**，按优先级排好的数组，每项
     {data: base64, name, label, kind, media, desc}
     label 是「它是谁」（`林小雨（常服）` / `雨夜巷口`），kind 是账单里的种类
     （character_sheet / location_reference / prop_reference / prev_frame / manual），
     desc 是「它长什么样」（`Asset.description`，压掉换行 + 超 120 字截断，没写是空串），
     media 是 image | video | audio——**同一个数组里三种媒体混着来**，服务端按
     media 分流（图进图生视频那条、音频进 S2V 那条）；
     用不上 label / kind / desc 可以忽略，但**顺序必须当成语义**——第 1 个最重要。
     一个参考素材都没有时这个键不出现（不是空数组）
  resp {task_id}            （也接受 {id}）

GET {base}/tasks/{task_id}
  resp {status, progress, output_url, error}
  status 只认 queued | running | done | failed
  output_url 是相对路径时按 base 拼

GET {output_url}            —— 产物字节流

GET {base}/health           —— 「测试连接」用，非 2xx 就算不通
```

密钥走 `Authorization: Bearer <key>`（设置页的 `video.api_key`）。字段缺失、状态字不认识、
非 2xx，一律归一成带建议的 `AppError`——**绝不静默当成「还在跑」**。

这条合同由我们定，所以它天生收多个参考素材，**三种媒体都不限数量、不存在槽位不够的降级**：
账单采用了几个就发几个（`RefCapacity` 报「REST 合同」+ 不限），也不会往 prompt 里塞
「参考素材说明」那句话——`label` / `media` / `desc` 已经在 body 里，用不着靠文字对号。

## 5. comfy_workflow（兼容路径，不推荐）

老的做法：工作流导入工程 → 手工把**抽象槽位**绑到具体的「节点id.字段名」→ 校验 → 就绪。
它要求你逐字段维护绑定表，模型端一改图两边就要同步——这正是它被降级的原因。

可绑定的槽位（`services/workflows.py:25`）：
`prompt` / `negative_prompt` / `reference_image` / `first_frame` / `last_frame` /
`source_image` / `seed` / `steps` / `width` / `height` / `duration`

四种能力各自的必填槽位（`persistence/models_gen.py:19`，缺一个就不能标 `ready`）：

| 能力 | 必填槽位 | 缺失影响 |
| --- | --- | --- |
| `text2image` | `prompt` | 角色表与首帧无法出图 |
| `image2video` | `prompt` + `reference_image` | 绝大多数镜头无法生成 |
| `first_last_frame` | `first_frame` + `last_frame` | 依赖它的镜头无法生成 |
| `upscale` | `source_image` | 成片只能停留在生成分辨率 |

这条路还会用 `GET /object_info` 探测自定义节点，图里用到的节点没装就报
`COMFY_NODE_MISSING` 并点名节点包。

**已知限制**：`_run_legacy`（`services/generation.py:538`）只注入
`prompt` / `negative_prompt` / `seed` / `steps` / `duration` 五个值，**不注入任何图片**。
也就是说 `reference_image` / `first_frame` / `last_frame` / `source_image` 这几个槽位能绑、
能过校验，但运行时不会被填——首尾帧、图生视频在这条路上实际上跑不通。要做 R2V 请用
`comfy_preset` 或 `http_api`。`text2image` / `upscale` 两种能力也只存在于这张能力矩阵里，
当前没有任何入队路径会用到它们（`enqueue_shot` 只会产出 `image2video` /
`first_last_frame`）。

## 5.5 另外两条链的入口：二次处理与音源

这两条链**不出新画面**，所以它们不在上面那张 R2V 的表里，但走的是同一套「节点标题约定」：
本工具照旧只按标题填值，不解析、不校验、不改写图里的 lora 与加速节点。

### 二次处理（超分 / 插帧 / 重做）

一份**另存的图**，唯一多出来的必需入口是「要处理的那一段从哪儿进去」：

| 节点标题 | 填什么 | 会往哪个字段填 | 必需性 |
| --- | --- | --- | --- |
| `AIVS_SOURCE_VIDEO` | **要处理的那一段成片**（文件名） | `video` / `file` / `filename` / `path` / `url` / `value` | **必需**（缺它 `refine_ready=false`） |
| `AIVS_PROMPT` | 有些重做图也收提示词 | 同上表 | 可选 |
| `AIVS_DURATION` / `AIVS_SEED` | 同上表 | 同上表 | 可选 |

**它和 `AIVS_REF_VIDEO_1` 是两件事**，绝不能互相顶替：参考视频是「动作跟着它走」，
源视频是「就把这一段本身重新算一遍」。图里两个都标了也没关系，本工具往前者填的是
账单里的参考素材，往后者填的是 `params.source_version_id` 指名的那一版。

设置里选哪一份图：`refine.preset`，留空退回 `video.preset`（很多人就一份图）。
**刻意没有单独的地址 / 密钥**——超分与出画面跑在同一台机器上是常态。

产物是**同一个镜头上的新版本**（`source="refined"` + `parent_version_id` 记血缘），
所以采用、装配、导出一行不用改；不满意就把旧那一版再采用回去，旧版本一条都不删。

### 音源（配音 / 环境音）

也是一份另存的图，两个入口**二选一即可**（`audio_ready` 就是这个判断）：

| 节点标题 | 填什么 | 会往哪个字段填 | 必需性 |
| --- | --- | --- | --- |
| `AIVS_AUDIO_TEXT` | **台词**（说什么） | `text` / `prompt` / `string` / `value` | 出人声时必需 |
| `AIVS_AUDIO_PROMPT` | **声音描述**（音色 / 情绪 / 环境音） | 同上 | 只出环境音 / 音乐时用它 |
| `AIVS_VOICE_REF` | 音色参考音频（几秒干净人声） | `audio` / `file` / `filename` / `path` / `url` / `value` | 可选；声音克隆那类图要它 |
| `AIVS_SOURCE_VIDEO` | 镜头采用的那段画面（口型驱动要它） | 同上 | 可选；没有它时只写一条 note，不失败 |
| `AIVS_AUDIO_DURATION` / `AIVS_AUDIO_SEED` | 时长（秒）/ 种子 | 同视频那两个 | 可选 |

音源那条链**有自己的一整套设置**（`audio.provider` / `audio.base_url` / `audio.api_key` /
`audio.preset` / `audio.timeout`）：TTS 在 CPU 上就够，视频要 24G 显存，两者常常不在一台机器上。
默认 `audio.provider="none"`——**没配音源不是异常**：配音入口回 `MISSING_CAPABILITY`，
建议里写明「把外面做好的音频导入成这个镜头的音频版本」
（`POST /projects/{pid}/shots/{shot_id}/audio/import`），手动那条路走完全流程，
装配、静音、配音轨全都照旧。

产物是同一个镜头上 `kind="audio"` 的另一版，落**第二个采用指针**
`Shot.current_audio_version_id`；装配时它进专门的配音轨并把画面那一段静音。
**画面一个字节都不重跑**——这条链存在的全部理由就是这一句。

## 6. 完全不需要生成能力的路径

生成服务离线不是崩溃，只是 `COMFY_OFFLINE` + 建议，下面这些照常能走：

- **手动导入成片**：先把视频登记成资产（`POST /projects/{pid}/assets/upload` 或
  `/assets/register`），再 `POST /projects/{pid}/shots/{shot_id}/versions` 带上 `asset_id`
  建一个 `source="manual"` 的版本。链路后半段（Clip → Timeline → 导出）完全不依赖 AI。
- **抽帧**：`services/frames.py`，只要 FFmpeg（应用自带一份，见 CLAUDE.md 的「内置 FFmpeg」）。
- **时间线与导出**：`services/timeline.py`，纯 FFmpeg。`GET /export/command` 只产出参数计划，
  `POST /export` 才真起进程。
- **分镜、上下文账单、素材库、采用**：全都在本地库里，与模型端无关。

LLM 同理：默认 `llm_provider="none"`，AI 入口返回 `LLM_UNAVAILABLE` 且建议里必须写明手动
路径。Manual 模式必须能走完全流程。

## 6.5 内置 SKILL：四种参考图形态下的 prompt 结构

「首帧 + 末帧」「只有首帧」「只有末帧」「只有参考素材」这四种形态，prompt 该怎么写并不一样——
有首帧时要先写一句锚定语把画面钉在那张图上，只有末帧时反过来要写「最后落到 Picture 1 的构图」。
这四份写法做成了**内置 SKILL**（`backend/app/ai/skills/video_prompt.py`，内容是 Python 字符串
常量而不是随包分发的 `.md`，照 `app/ai/prompts.py` 的先例——冻结成 sidecar 时不需要额外
`--add-data`），由 AI 导演按需读取：

| 首帧 | 末帧 | 参考素材 | SKILL | 界面上叫 |
| --- | --- | --- | --- | --- |
| 有 | 有 | 任意 | `flf` | 首帧 + 末帧 → 视频（FL2VA） |
| 有 | 无 | 任意 | `i2v` | 首帧 → 视频（I2VA） |
| 无 | 有 | 任意 | `l2v` | 末帧 → 视频（L2VA） |
| 无 | 无 | 有 | `ref` | 参考素材 → 视频（Ref2VA） |
| 无 | 无 | 无 | `ref` | 同上（退化，只写主体定义） |

三个导出函数，**渐进披露**是它的要点：

- `catalog()` —— 每份一行（`name` + 标题 + 什么时候用它）。**只有这几行进系统提示词。**
- `render(name)` —— 那一份的全文（写法 + 范例）。由 `read_skill` 工具按需取一份，
  不认识的名字报 `VALIDATION_ERROR`（四要素齐全）。一次只读需要的那一份，
  是「拆长剧本不再超时」的另一半原因。
- `pick(has_first, has_last, has_refs)` —— 按槽位选一份。后端兜底与界面提示共用这一处口径，
  对应的就是 `Shot.first_frame_asset_id` / `last_frame_asset_id`（见 CLAUDE.md 的首 / 末帧槽位段）。

**无配乐那条硬约束不在 SKILL 里重写。** SKILL 的 `AUDIO_RULE` 只说一句「`non_diegetic_music`
一节固定填 `none（本项目不生成配乐）`」——字段保留（模型照官方结构写才不容易漏别的段），
真正的兜底仍然是 `prompts.with_shot_audio_policy()`（`SHOT_AUDIO_PROMPT_SUFFIX` +
`SHOT_AUDIO_NEGATIVE_TERMS`：`background music, BGM, soundtrack, musical score` 进负向词）。
两处都写只会打架。

模型照 SKILL 写出来的是**三段字段**（`camera_motion` / `visual_prompt` / `audio_dialogue`
+ `negative_prompt`，外加一个 `skill` 说它照哪一份写的），最终那段正向 prompt 由
`prompts.format_shot_prompt()` 拼成 `[SHOT n]` 四段格式再过 `with_shot_audio_policy()`。
锚定语（"begins in the composition established by Picture 1…"）是模型自己照 SKILL 写的，
**代码不改写它的文字**。

- [ ] `AIVS_DURATION` 贴在吃**秒数**的输入上（吃帧数的别贴）
- [ ] `AIVS_SEED` 贴在采样器的 `seed` / `noise_seed` 上（不贴就是图里那个固定值）

## 8. 加一种新的调用方式

按适配层的口径来，业务层一行都不用改：

1. 在 `app/generation/providers/` 下新建一个文件，实现 `VideoProvider` 四件事
   （`probe` / `submit` / `poll` / `fetch`，见 `providers/base.py:85`）；
2. 在 `registry.py` 的 `BUILTIN` 加一行、在 `LABELS` 加一行标签；
3. **参考素材（`req.refs`）要么真的送过去，要么把降级写进 `req.notes`**——不许因为带不了标签
   或者槽位不够就把它悄悄丢掉，那正是「人物形象跑偏」查不出原因的来源。三种媒体
   （`RefAsset.media`）**分开算容量**：能收几张图与能收几段音频是两个数，`probe()` 回的
   `RefCapacity` 要按族填（`video=` / `audio=`），收不了的那一族回 0 并在 note 里说出来，
   绝不把一段视频当图片送出去；
4. **首帧不许自己挑**：只用 `req.first_frame`（它来自镜头上那个显式槽位），
   `refs` 里优先级最高的那一条仍然只是参考素材。要在没有首帧入口时降级的话，
   照 `comfy_preset._refs` 的做法插到参考图 1 并留一条 note；
5. 出网请求要归一成带四要素的 `AppError`（离线用 `COMFY_OFFLINE`、缺配置用
   `MISSING_CAPABILITY`、服务端不按合同用 `WORKFLOW_ERROR`）；
6. 产物必须 `fetch` 回字节落进工程，不能只存在服务端。

不要在 service 层写 `if provider == "xxx"`——那是硬约束 1，差异只能待在适配器里。
