# 功能开发文档

> 配套文档：[01-技术栈与架构](01-技术栈与架构.md) · [03-数据模型与接口契约](03-数据模型与接口契约.md)

## 0. 文档约定

- **必须**＝阶段一 MVP 范围内；**应当**＝阶段二；**可以**＝阶段三备选。
- 一切功能都服务于唯一主链路，任何需求若不落在这条链路上，一律推迟：

```text
Character → Appearance → Scene → Shot → Context → Generation
        → GenerationVersion → Clip → Timeline → Final Video
```

- 三种工作模式贯穿全系统，任何 AI 功能都必须有等价的手工路径：
  `AI Auto`（AI 直接产出并落库）/ `AI Assisted`（AI 出建议，用户逐项接受）/ `Manual`（完全手工，LLM 可未配置）。

## 3. 模块功能规格

### 3.1 Project

**数据**：名称、简介、封面、风格（style preset）、分辨率、FPS、默认生成模型、默认 Workflow、默认 Prompt Style、默认画面比例。

**功能**
- 必须：新建（选择磁盘目录，生成完整工程目录 + SQLite + 迁移）、打开（校验 `project.aivs.json` schema 版本，必要时自动升级）、最近打开列表、项目设置编辑。
- 必须：Dashboard 统计 = Scene 数 / Shot 数 / 已生成 Shot / 待生成 Shot / 总时长（按各 Shot 当前版本时长求和）/ 最近 10 条 Job / ComfyUI+GPU 状态 / 队列摘要。
- 应当：项目模板（默认风格 + 默认 Workflow 绑定）、导出工程为 zip。

**验收**：新建项目后目录结构完整；关闭再打开数据无损；修改默认分辨率后新建 Shot 继承新值、已有 Shot 不被改动。

### 3.2 Character Studio

**层级**：`Character → Appearance → CharacterSheet → SheetVersion`。左树右板。

- 必须：Character CRUD（Name/Age/Gender/Personality/AppearanceDescription/PersistentTraits/Background/DefaultAppearance）。
- 必须：Appearance CRUD，字段 = 年龄 / 服装 / 发型 / 配饰 / 身体状态 / 特殊状态 / 描述 / LoRA 引用 / Sheet 版本列表。
- 必须：**Appearance 继承**。`parent_appearance_id` 非空时，继承 `face_identity / hair / body_shape / persistent_traits`，覆写 `age / costume / accessories / state`。UI 用「继承 / 覆写」双色标记每个字段，可逐字段「断开继承」。
- 必须：Character Sheet 生成（走 ComfyUI 图像 Workflow），一次产出 N 个候选；Sheet 为**多视角单图**（Front / 3-4 / Side / Back / Full Body / Half Body）。
- 必须：Sheet 的 `view_regions`（每个视角的归一化矩形），支持自动检测失败时手工框选；Context Resolver 依赖它做动态 Crop。
- 必须：版本管理——版本列表、并排比较（2/4 宫格）、设为当前版本、保留全部生成参数（prompt/model/seed/workflow）。
- 必须：基于已有 Appearance 派生新 Appearance 的「变更表单」（改年龄 / 改服装 / 改状态 / 保留疤痕），提交后生成 4 个候选。
- 应当：LoRA 绑定与触发词；人脸嵌入（face embedding）辅助一致性校验。

**验收**：`张伟/默认` → 派生 `警察时期`，只改 Age+Costume，生成 4 候选，选定 v3 为当前；随后任一 Shot 选择「张伟·警察时期」时，Context 自动引用 Sheet v3 且能按镜头类型裁出 Full Body。

### 3.3 Location Studio

- 必须：Location CRUD，字段 = 描述 / 建筑 / 环境 / 光线 / 时间 / 天气 / 风格。
- 必须：**Variant**（Day / Night / Rain / Snow / 自定义）与 **Scene Reference** 版本管理，结构与 Appearance/Sheet 对称。
- 必须：多机位参考生成（Wide / Medium / Detail / 不同朝向），作为不同 Reference 存在同一 Variant 下。
- 应当：Variant 之间的继承（Night 继承 Day 的建筑与布局，仅改光线/天气）。

### 3.4 Props

- 应当：Prop CRUD（描述 / 参考图 / 版本）、被哪些 Scene/Shot 引用的反向查询。
- 阶段一：数据表与 API 建好，UI 只做列表 + 引用选择器，Context Resolver 支持注入 Prop Reference。

### 3.5 Story / AI Director

**布局**：左＝剧本编辑器（纯文本 / 分幕），中＝Breakdown 结果，右＝Director 面板（模式切换 + 逐项建议）。

- 必须（Manual）：手工创建 Scene、手工创建 Shot、手工填写描述与 Cast。
- 必须（AI Assisted）：粘贴剧本 → LLM 输出结构化 Breakdown（Characters / Locations / Props / Scenes / Shots）→ **逐项 Diff 审阅**（新建/合并到已有角色/忽略）→ 确认后落库。
- 必须：识别到的角色可映射到已有 Character（避免重复建人），映射面板给出相似度提示。
- 必须：Shot 级建议 = Prompt 草稿 / Camera / Duration / 建议生成模式 / Cast + Character State。
- 应当（AI Auto）：一键从剧本直达完整 Storyboard（内部仍走同一 Breakdown 管道，只是自动接受全部建议）。
- 应当：连续性检查（角色形象在相邻 Shot 突变、Cast 缺失、Location 未指定、依赖环）→ 输出问题清单，可跳转修复。
- **硬约束**：LLM 输出必须经 Pydantic schema 校验后才允许落库；校验失败展示原始输出让用户手工修正，绝不静默丢弃。

### 3.6 Scene 与 Scene Cast

- 必须：Scene 字段 = 序号 / 标题 / 描述 / Location + Variant / 时间 / 情绪 / 默认 Workflow 覆写。
- 必须：**Scene Cast** = 本 Scene 出场角色 + 各自使用的 Appearance。禁止在 Shot 层直接从全项目角色库选人——Shot Cast 只能从 Scene Cast 取子集（可在 Shot 内一键「加入 Scene Cast」补充）。
- 必须：Scene 排序（拖拽），排序变化联动 Timeline 的 Scene 分组顺序。

### 3.7 Storyboard

- 必须：Scene 泳道纵向排列，每道内 Shot 卡片横向排列，虚拟滚动。
- 必须：Shot Card 显示 = 缩略图（当前版本首帧）/ 时长 / Cast 头像条 / 状态徽标 / 当前版本号 / 生成次数 / **Context 完备度指示**（缺参考、缺上一帧、Workflow 不匹配用不同颜色）。
- 必须：状态集合 `Draft / Waiting / Generating / Completed / Failed / NeedsReview`；`Generating` 卡片内嵌进度环。
- 必须：批量操作 = 生成本 Scene / 生成选中 Shot / 每个 Shot 生成 N 个候选 / 单 Shot 重跑 / Scene 重跑 / 全项目生成待生成 Shot。
- 必须：拖拽调整 Shot 顺序、跨 Scene 移动 Shot、复制 Shot（复制 Prompt/Cast/Context，不复制 Version）。
- 应当：卡片悬停播放代理视频（hover scrub）。

### 3.8 Shot Editor（核心页面）

```text
┌──────────────┬───────────────────────────┬─────────────────────┐
│ Shot 列表     │ 预览 / 版本对比            │ Inspector（Tab）     │
│ (同 Scene)   │  ┌─────────────────────┐  │  · Basic            │
│              │  │  Player / A-B 对比   │  │  · Cast & State     │
│              │  └─────────────────────┘  │  · Context Inspector│
│              │  VersionRail  V1 V2 V3 V4 │  · Prompt           │
│              │  ─────────────────────────│  · Workflow & Params│
│              │  Story Description 编辑区  │  · Dependencies     │
└──────────────┴───────────────────────────┴─────────────────────┘
```

- 必须：Basic = 序号 / 描述 / Duration / Camera（角度+运动+焦段）/ Location 覆写 / Generation Mode（默认 `Auto`）。
- 必须：Cast & State = 从 Scene Cast 勾选角色，逐角色指定 Appearance 与 **Character State**（`existing / entering / background`）。
- 必须：Prompt Tab = 用户输入区 + 「编译预览」只读区（展示分层拼装结果）+ Prompt 版本历史。
- 必须：Workflow Tab = 自动选择结果 + 手动覆写 + 参数（seed / steps / cfg / 候选数 N / 分辨率 / 时长）。
- 必须：Dependencies Tab = 声明 `depends_on`（默认自动指向前一 Shot，可解除）、连续性强度（`strict` 必须等上游最终版本 / `optional` 可提前跑）。
- 必须：VersionRail = 版本缩略图条，操作 Preview / Compare / Set Current / Add to Timeline / Continue from this Version / Regenerate。

### 3.9 Context Resolver（系统的大脑）

**输入**：`shot_id` + 可选覆写。**输出**：`ResolvedContext`（见 03 文档）。**原则**：绝不加载整个项目。

解析步骤：

1. **收集候选**：Shot Cast → 各角色 Appearance；Scene Location + Variant；Shot Props；Style Reference（项目级）。
2. **按 Character State 决定引用策略**
   - `entering`：必须注入 Character Sheet 视角裁图（首次出场需要强身份约束）。
   - `existing`：优先继承上一 Shot 的尾帧/视频状态；Sheet 仅作弱参考（可按 Workflow 能力上限裁掉）。
   - `background`：不注入资产，只在 Prompt 中用泛化描述（如「远处两名警察」）。
3. **视角选择**：按 Camera 类型映射 Sheet 视角 —— `close-up→Face`、`medium→3/4`、`full/wide→Full Body`、`back→Back`、明确未知→`Entire Sheet`。裁图结果缓存到 `cache/crops/`。
4. **连续性输入**：若存在 `depends_on` 且上游有当前版本 → 注入 `previous_last_frame`；若本 Shot 是同一镜头延续 → 注入 `previous_video`（走 Extend）。
5. **预算裁剪**：按目标 Workflow 声明的输入槽位上限（如最多 2 张参考图）按优先级裁剪：`previous_frame > entering character > location > existing character > prop > style`。裁掉的项**必须**在 Context Inspector 中标为「因 Workflow 容量被省略」。
6. **缺失校验**：产出 `issues[]`（缺 Location、Appearance 无当前 Sheet、上游未生成等），阻塞级问题禁止入队。

### 3.10 Context Inspector

- 必须：以清单形式展示每一项 Context 的来源、版本、被裁区域缩略图、注入槽位、是否被省略。
- 必须：可增删改 —— 移除某项 / 添加任意资产 / 替换 Appearance / 替换 Location Reference / 替换上一帧（可从任意 Shot 任意版本选帧）/ 上传新参考图。
- 必须：手动覆写以 `shot_context_override` 独立存储，不污染自动解析逻辑；提供「恢复自动」按钮。
- 必须：展示最终 Prompt 版本与选定 Workflow，一键跳转 Workflow 详情。

### 3.11 Prompt Compiler

分层拼装（顺序固定、每层可开关、每层可编辑模板）：

```text
[Style] 项目风格 + Scene 风格覆写
[Character] 每个注入角色的身份描述（来自 Appearance 继承链的合并结果）
[Appearance] 服装 / 发型 / 配饰 / 状态
[Scene] Location 描述 + 时间 + 天气 + 光线
[Continuity] 承接上一镜的动作/位置描述
[Camera] 角度 + 运动 + 焦段
[Action] ← 用户输入的镜头内容（核心，永不被覆盖）
[Negative] 项目级 + Shot 级
```

- 必须：编译为纯函数，`compile(shot, resolved_context, templates) → CompiledPrompt`，可单测、可无 LLM 运行。
- 必须：Prompt 有独立版本记录；每个 GenerationVersion 冻结当时的编译结果与输入快照。
- 应当：LLM 润色作为可选后置步骤，产出仍写入 Prompt 版本，**不覆盖**用户 `[Action]` 原文。
- **硬约束**：Source of Truth 是 Character/Scene/Appearance/Shot/Asset 数据库，LLM 只是加工者。

### 3.12 Generation Mode 与长视频策略

用户侧默认 `Auto`；可强制 `T2V / I2V / R2V / Extend / V2V / StartEnd`。内部由 Context 决定，规则表：

| 情形 | 注入内容 | 落到的能力 |
|---|---|---|
| Scene 首个 Shot、无前序 | Character Sheet + Location Ref + Prompt | R2V（有参考图）或 T2V |
| 同 Scene 后续 Shot、机位延续 | Previous Last Frame + Prompt | I2V |
| 同一镜头继续延长 | Previous Video 尾段 + Prompt | Extend |
| 跨 Scene 第一镜 | Previous Last Frame + Character Ref + New Location Ref | R2V / I2V（视 Workflow 能力） |
| 新角色首次出场 | Character Sheet（强） | R2V |
| 需要指定落幅 | Start Frame + End Frame | StartEnd |
| 完全独立空镜 | Prompt only | T2V |
| 导入视频重制 | Source Clip + Prompt(+Ref) | V2V |

**长视频主路线**：`Scene N 视频 → 尾帧 → Scene N+1 Context → 视频 → 尾帧 …`，禁止连续纯 T2V 拼接。

### 3.13 Generation Queue 与依赖调度

- 必须：Job 状态机 `Draft → Queued → Running → Completed | Failed | Cancelled | NeedsReview`。
- 必须：DAG 调度 —— 无依赖并行（并发数 = 用户配置的 worker 数，默认 1，受 VRAM 限制）；`strict` 依赖必须等上游**当前版本被确认**；`optional` 依赖可提前跑。
- 必须：入队时检测依赖环并拒绝，给出环路径。
- 必须：Pause / Resume / Cancel / Retry（带原参数）/ 调整优先级 / 批量入队 / 拖拽排序。
- 必须：进度来自 ComfyUI `/ws`（节点级进度 → 归一化百分比），经后端事件总线广播到前端。
- 必须：断电/崩溃恢复 —— 启动时扫描 `Running` Job，用落库的 `prompt_id` 向 ComfyUI `/history` 认领结果；认领不到则标 `Failed` 并说明原因。
- 应当：依赖图可视化（Scene/Shot 节点 + 依赖边 + 状态颜色）。

### 3.14 Generation Version

- 必须：**永不覆盖、永不隐式删除**。每个版本冻结：Prompt 编译结果 / Workflow 快照（含 graph JSON）/ Model / Seed / 全部参数 / ResolvedContext 快照 / 输出视频 / 首帧 / 尾帧 / 代理 / 缩略图 / 时长 / 创建时间 / 耗时。
- 必须：操作 Preview / Compare（A-B 同步播放）/ Set Current / Add to Timeline / Continue from this Version / Regenerate（复用参数改 seed）。
- 必须：`Set Current` 会触发下游 `strict` 依赖 Shot 标记为 `NeedsReview`（因为其继承的尾帧变了），并提示是否重跑。
- 必须：手动删除版本需二次确认，并阻止删除被 Timeline 引用的版本。

### 3.15 导入视频 / AI 视频重制（阶段二）

- 应当：导入视频 → FFmpeg 场景切分（`scene detect` 阈值可调）+ 固定时长切分二选一 → 生成 `Clip01..ClipN`，落为一个 `ImportSession`。
- 应当：可将切分结果**映射为 Scene/Shot 结构**，从而复用整条 Storyboard/Context/Queue 流程。
- 应当：逐 Clip 或批量执行 AI 重绘 / 风格转换 / V2V / Extend / 局部修改 / Character Replace / Scene Replace / Object Replace。
- **硬约束**：AI 输出是新 Version，原始视频永远是 `version 0`，不可覆盖。

### 3.16 统一 Clip 模型

生成与重制共用同一数据模型：`Clip{ source: none | original_video | shot, operation: generate | ai_edit, workflow, versions[] }`。
Timeline 只认 `Clip → 当前 Version`，不关心它是生成的还是重制的。

### 3.17 Timeline

**硬约束**：Timeline 是确定性编辑系统，**不依赖 AI 也能完整运行**。

- 必须：轨道模型 = 多视频轨 + 多音频轨 + 字幕轨；Scene 以「分组标记」形式覆盖在视频轨上（不是独立轨）。
- 必须：编辑操作 Add / Move / Trim（含 ripple 与 roll 两种）/ Split / Delete / **Replace Version** / Duplicate / Speed / Crop / Volume / Fade / Basic Transform（位置/缩放/旋转/不透明度）。
- 必须：吸附（Clip 边界 / 播放头 / Scene 边界）、磁吸开关、多选、框选、复制粘贴、撤销重做（命令栈 ≥ 100 步）。
- 必须：`Auto-Assemble` —— 按 Scene/Shot 顺序把各 Shot 当前版本自动铺入视频轨，已存在的 Clip 按 `shot_id` 就地替换而非重复插入。
- 必须：Shot 版本切换后 Timeline 对应 Clip 显示「版本已更新」徽标，一键同步。
- 必须：预览用代理视频；播放头 seek 精度到帧；播放时跨 Clip 无缝切换（双 video 元素预载 + 交替）。
- 必须：渲染层为 Canvas 2D，支持时间轴缩放（帧级 ~ 全片级）、轨道高度调整、缩略图条（按缩放级别抽帧密度自适应）、音频波形。

### 3.18 Transitions

- 必须：`Cut / Cross Dissolve / Fade / Dip to Black / Dip to White`。
- 应当：`Push / Slide / Zoom / Blur`。
- 必须：拖到两 Clip 交界处生成转场，可调时长与曲线；由人工决定。
- 可以：AI 依据 Scene 关系推荐转场（仅建议，需用户接受）。

### 3.19 Effects

- 必须：`Color`（亮度/对比/饱和/色温）、`LUT`、`Film Grain`、`Blur`、`Vignette`。
- 应当：`Glow / Glitch / VHS / Light Leak / Camera Shake`。
- 必须：Effect 拖到 Clip、参数面板、多个叠加与排序、保存为 Preset。
- 实现方式：预览走 CSS filter / Canvas 近似；**导出走 FFmpeg filter_complex 精确渲染**（两者参数映射必须有单测比对）。
- 明确不做：Premiere / AE 级效果体系。

### 3.20 Audio（阶段二）

- 应当：背景音乐 / 人声 / 音效轨、音量、淡入淡出、音频裁剪、基础混音（增益 + 简单 ducking）。
- 可以：AI Voice / AI Music / AI SFX（沿用同一 Job 队列与 Version 模型）。

### 3.21 Subtitle（阶段二）

- 应当：手工字幕（时间码编辑）、样式（字体/字号/描边/阴影/位置）、SRT/ASS 导入导出。
- 可以：自动字幕（Whisper 本地）。

### 3.22 Workflow Manager

- 必须：Workflow 列表（官方内置 + 用户导入），每条声明 **Capability 集合**：
  `text / image / video / character_reference / scene_reference / previous_frame / start_end_frame / extend / lora / controlnet / output_video / output_image`，附带 `max_ref_images / max_duration / supported_resolutions`。
- 必须：导入 ComfyUI 导出的 `workflow_api.json`，做**节点绑定**：`prompt / negative / image_slot[i] / video / lora / seed / width / height / length / output` → 具体 node.input。
- 必须：绑定校验（节点存在、类型匹配、必填槽位齐全），校验失败列明缺失项。
- 必须：Capability Matrix 视图，横轴能力纵轴 Workflow，一眼看出「谁支持 Character Reference」。
- 必须：Workflow Resolver 打分规则 —— 必需能力全满足为前提，再比较（能力冗余度低 / 与项目默认一致 / 用户最近使用），结果与理由一并返回给 UI。
- 应当：ComfyUI 在线探测（`/object_info`）校验所需自定义节点是否安装，缺失时给出节点名。
- **普通用户完全不需要理解 Node Graph**：默认使用内置 Workflow，只有导入自定义时才进入绑定编辑器。

### 3.23 Asset Library

- 必须：统一管理 Characters / Appearances / CharacterSheets / Locations / Props / References / LoRAs / Videos / Frames / Audio / Workflows。
- 必须：每个 Asset 有 `asset_id / type / owner(所属实体) / tags / version / source(generated|imported|uploaded) / usage(被引用位置) / created_at / file_path / hash`。
- 必须：按类型/标签/使用状态过滤，网格 + 详情，反向引用列表（点击跳转到引用它的 Shot）。
- 必须：孤儿资产检测（无任何引用）与手动清理。

### 3.24 错误处理

- 必须：所有错误结构化 `{ code, title, detail, suggestions[], related_ids }`，禁止静默失败、禁止只打印到控制台。
- 必须错误码覆盖：`WORKFLOW_ERROR / MISSING_ASSET / MISSING_INPUT / MISSING_CAPABILITY / COMFY_OFFLINE / COMFY_NODE_MISSING / GPU_OOM / INVALID_WORKFLOW / FFMPEG_ERROR / DISK_FULL / DEPENDENCY_CYCLE / UPSTREAM_NOT_READY / SCHEMA_MISMATCH`。
- 必须：示例文案格式
  > **当前 Workflow 不支持 Character Reference**
  > `Wan T2V` 未声明 `character_reference` 能力，无法注入「张伟 / 警察时期」。
  > 建议：① 切换到 `Wan I2V` 或 `Wan R2V`；② 为当前 Workflow 补充 image 槽位绑定；③ 移除该角色参考后仅用 Prompt 生成。
- 必须：Job 失败保留完整现场（提交的 graph JSON、ComfyUI 返回、stderr），Job 详情页可查看与复制。

### 3.25 Export

- 必须：导出范围（全片 / 选中 Scene / 入出点）、分辨率、FPS、编码（H.264 / H.265）、码率、音频参数。
- 必须：导出前预检（缺失文件、未生成 Shot、时长为 0 的 Clip）并列出问题。
- 必须：导出为后台 Job，进度来自 FFmpeg 输出解析，可取消。
- 必须：导出使用原始素材（非代理），Effects/Transitions 转换为 `filter_complex`。
- 应当：导出 EDL / XML 到 Premiere / Resolve；导出单 Scene 序列。

## 4. 关键状态机

```text
Shot.status
  draft ──(context 完备)──> ready ──(入队)──> generating
    generating ──成功──> completed ──(上游版本变更)──> needs_review
    generating ──失败──> failed ──(retry)──> generating
    completed ──(手动重跑)──> generating

Job.status
  draft → queued → running → completed | failed | cancelled
  queued ──(依赖未就绪)──> waiting_upstream → queued
  failed ──(retry)──> queued
```

`Shot.status` 由其 Job 与当前版本推导，**不允许前端直接写**。

## 5. 开发里程碑

### M0 · 地基（第 1–2 周）
- Monorepo 骨架（`frontend/` `backend/` `tauri/` `docs/`）、lint/format/CI 脚本。
- FastAPI + SQLAlchemy + Alembic + SQLite 打通；`/health`；WS 事件总线雏形。
- Tauri 壳 + sidecar 启动/健康检查/退出；随机端口 + 握手 token。
- OpenAPI → 前端类型生成脚本；Design Token + 基础组件（Panel/Split/Card/Button/Field/StatusDot）。
- **验收**：桌面应用启动，UI 能读到后端 `/health` 与版本号。

### M1 · 工程与资产（第 3–5 周）
- Project 新建/打开/设置/Dashboard；工程目录与 schema 版本校验。
- Character / Appearance（含继承）/ CharacterSheet / SheetVersion 全套 CRUD + UI。
- Location / Variant / Reference；Props 最小实现。
- Asset Library 基础（登记、缩略图、反向引用）。
- **验收**：可手工建出「张伟 + 默认/警察时期 + 咖啡馆(日/夜)」，Sheet 用本地上传图占位。

### M2 · ComfyUI 与图像生成（第 6–8 周）
- ComfyUI Client（HTTP + `/ws`）、连通性与节点探测。
- Workflow Registry + Capability 声明 + 导入 + Node 绑定编辑器 + 绑定校验。
- Workflow Adapter（base + generic_binding）；Job 表 + 单 worker 调度器。
- Character Sheet 生成（N 候选、版本、设为当前、view_regions 框选）。
- **验收**：从文字生成一张 Character Sheet 的 4 个候选并设定当前版本，失败时给出结构化错误。

### M3 · 故事与 Storyboard（第 9–11 周）
- Story 编辑；Scene / Scene Cast / Shot CRUD；Shot 排序与跨 Scene 移动。
- Storyboard 泳道 + Shot Card + 状态徽标 + 批量选择。
- Shot Editor 全部 Tab（Basic / Cast&State / Prompt / Workflow / Dependencies）。
- LLM Provider 抽象 + AI Director（Assisted 模式 + schema 校验 + Diff 审阅）；Manual 模式全通。
- **验收**：无 LLM 配置下可纯手工建出 3 Scene × 4 Shot 的完整 Storyboard。

### M4 · Context + Prompt + 视频生成（第 12–15 周）
- Context Resolver（全部 6 步，含 State 策略、Sheet 裁切、预算裁剪、issues）+ 单测。
- Context Inspector（查看/移除/添加/替换/恢复自动）。
- Prompt Compiler（分层、模板、版本）+ 单测。
- 视频生成全链路；GenerationVersion；尾帧/首帧/缩略图/代理产出。
- DAG 调度器（依赖、并发、strict/optional、环检测、崩溃恢复）+ Queue UI（Pause/Resume/Cancel/Retry/优先级）。
- **验收**：Shot 01 生成 → 选定版本 → Shot 02 自动继承尾帧生成 → 单独重跑 Shot 02 得到 V2 并设为当前 → Shot 03 感知变更标记 NeedsReview。

### M5 · Timeline 与导出（第 16–19 周）
- Canvas Timeline 渲染器（缩放/轨道/缩略图/波形/命中测试）。
- 编辑命令集 + 撤销栈 + 吸附 + 多选；Auto-Assemble；Replace Version。
- 预览监视器（代理、帧级 seek、跨 Clip 无缝播放）。
- 基础转场（Cut/Dissolve/Fade/Dip）+ 基础效果（Color/LUT/Grain/Blur/Vignette）。
- Export Job（预检、FFmpeg filter_complex、进度、取消）。
- **验收**：跑通文档「第一条完整链路」，导出一段 ≥ 2 分钟、跨 3 个 Scene 的成片。

### M6 · 阶段二（第 20 周起，按优先级排）
导入视频与 AI 重制（V2V 全链路）→ Audio → Subtitle → 更多 Effects/Transitions → AI Auto 一键成片 → 连续性检查增强 → EDL/XML 导出。

## 6. 非功能需求

| 项 | 目标 |
|---|---|
| 冷启动 | ≤ 3s 到可交互（sidecar 就绪前展示连接态） |
| Storyboard | 500 Shot 卡片滚动 ≥ 50fps（虚拟滚动 + 缩略图懒加载） |
| Timeline | 8 轨 × 300 Clip 缩放/拖拽 ≥ 50fps |
| 预览 seek | 代理视频 ≤ 150ms 出画 |
| 数据安全 | 所有写操作事务化；生成产物先写临时文件再原子改名 |
| 可移植 | 工程目录整体拷贝到另一台机器可直接打开（路径全相对） |
| 安全 | sidecar 仅监听 127.0.0.1 + 握手 token；不上传任何工程数据；LLM/云服务默认关闭 |
| 可观测 | 每个 Job 保留 request/graph/result/stderr；前端日志面板可导出 |
| 国际化 | 文案抽到 i18n（zh-CN 首发，预留 en-US） |
| 无障碍 | 全键盘可达、焦点可见、对比度 ≥ 4.5:1（深色主题下） |

## 7. 设计语言要点

- 深色为唯一首发主题；三层背景（`#111316 / #17191d / #1e2126`）+ 单一强调色（青绿系）+ 状态色（灰=Draft、蓝=Queued、黄=Running、绿=Completed、红=Failed、橙=NeedsReview）。
- 高信息密度：基础行高 28px，卡片间距 8px，字号 12/13px 为主，`tabular-nums` 显示时间码与数值。
- 缩略图优先：任何列表项都应有视觉预览；无预览时用占位图 + 状态说明，不留空白。
- 面板可拖拽调宽、可折叠、布局记忆到本地。
- 不做 SaaS Dashboard 观感：没有大圆角卡片、没有大面积留白、没有营销式配图。
