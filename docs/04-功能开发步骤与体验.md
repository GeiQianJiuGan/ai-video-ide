# 04 · 推荐的功能开发步骤与使用体验

本文回答两个问题：**先做什么、后做什么**，以及**每一步做完之后，人坐在软件前面的真实体验是什么样**。

顺序原则（与核心链路一致，不可跳跃）：

```
Character → Appearance → Scene → Shot → Context → Generation → Version → Clip → Timeline → Final Video
```

每一步都遵守四条硬约束：业务层不绑定具体视频模型；LLM 永远可绕过；生成版本永不覆盖；绝不静默失败。

当前状态：**Step 1–10 均已落地**（后端全量 + 前端全部接上；`features.ts` 里 15 个功能都是
`ready: true`）。下面按顺序记录每一步做了什么、做完之后人坐在软件前面看到什么——新加功能时
照这个格式往后续写。

---

## Step 1 · 项目容器（M1）

**目标**：让「打开一个项目」这件事真正成立，之后所有数据都有地方落。

**做的事**

- `POST /projects`（在指定目录创建工程）、`POST /projects/open`、`GET /projects/recent`
- 工程目录：`project.aivs.json` + `project.db`（SQLite WAL）+ `assets/` + `generations/` + `proxies/`
- Alembic 按项目库迁移（`-x db=<path>`），打开旧工程时自动升级并显示 schema 版本
- 前端：起始页接上真实列表；标题栏面包屑显示项目名；Activity Bar 解锁

**使用体验**

你打开应用，落在起始页。点「新建项目」，选一个空目录，填名字、分辨率 1920×1080、帧率 25、时长单位帧。回车之后窗口标题栏立刻变成 `我的短片 › 项目概览`，左侧导航栏原本灰掉的十个图标同时亮起——**项目打开与否，看一眼导航栏就知道**。

你去资源管理器看那个目录：五个子项一目了然，`project.db` 只有几十 KB。你把整个目录拷到移动硬盘，在另一台机器上点「打开项目」选它，schema 版本自动从 1 升到 2，状态条上出现一行「工程已升级 schema 1 → 2」，数据一条不少。

如果你选的目录里已经有一个非本工程的 `project.db`，不会静默覆盖：弹出的错误写着「目录已被占用」「detail: 该目录存在无法识别的 project.db」，以及三条建议——换个空目录 / 备份后重试 / 以只读方式检查。

## Step 2 · 角色与形象（M1）

**目标**：把「这个人长什么样」固定下来，让后面每个镜头引用同一个真源。

**做的事**

- Character / Appearance 两级；Appearance 支持从父形象派生，`face/hair/body/traits` 继承，`age/costume/state` 覆写
- Character Sheet 占位（真正出图在 Step 4 之后接通）
- 前端：角色工作台三栏——列表 / 形象与角色表 / 形象属性

**使用体验**

进「角色」。左栏空的，但空状态里写着「还没有角色 · 新建一个只需要名字」，旁边就是按钮——**不存在没有下一步的空白区域**。

你建「林昭」，只填名字就保存了，外观留空。右栏属性面板列出脸型、发型、体型、服装、状态五组字段，全是「未填写」。你填了脸型和发型，其余不管。

然后你点「派生形象」，基于「少年」派生出「成年」。新形象的脸型和发型直接显示为浅色的继承值，旁边有个小锁标记；你把服装改成「黑色长衫」，这一项立刻变成实色并出现「已覆写」的标记，点一下可以还原成继承。**你永远知道每个字段的值是自己填的还是继承来的。**

---

## Step 3 · 场景、道具与资产库（M1）

**目标**：补齐素材层的另外两类真源，并让所有落盘文件从第一天起就有总账。

**做的事**

- Location / Variant（日夜雨雪）/ Scene Reference
- Prop 与参考图版本
- Asset 统一登记 + 反向引用 + 孤儿检测

**使用体验**

你建「城南旧宅」，再加两个变体：「白天」和「雨夜」。变体只写时间、天气、光线三句描述，其余从地点继承。右栏底部有一行「被 0 个 Scene 引用」——这一行以后会变成可点的跳转列表。

你上传一把伞的照片建道具「油纸伞」。进「资产库」，按类型筛「道具图」，网格里就是这张图：分辨率、大小、创建时间、来源标为「手动上传」。右栏「引用关系」写着「被 1 个道具引用」。你点「扫描孤儿资产」，列出三个没人引用的临时文件，各自标了大小，你勾选删除——**删之前你已经看到删掉会破坏什么，或者确认不会破坏任何东西。**

---

## Step 4 · Workflow 管理与能力矩阵（M2）

**目标**：把 ComfyUI 的工作流登记成「能力」。从这一步起，业务层永远不知道模型叫什么名字。

**做的事**

- Capability 声明：`text2image` / `image2video` / `first_last_frame` / `upscale`
- 导入 `workflow_api.json`，把 prompt / 参考图 / 时长 / 种子 / 步数绑定到具体节点字段
- 绑定校验 + ComfyUI 自定义节点探测
- Capability Matrix：哪些能力已就绪、哪些缺

**使用体验**

你在 ComfyUI 里导出 API 格式的 json，拖进「流程」页。系统解析出节点树，主区左边是节点列表，右边是待绑定的输入槽：`prompt`、`negative_prompt`、`reference_image`、`seed`、`steps`。你把 `prompt` 拖到 `CLIPTextEncode.text` 上，槽位变绿。

你点「校验绑定」。结果是红的：「缺少自定义节点 `WanVideoWrapper`」，detail 里给出 ComfyUI 侧的节点名与出现位置，建议三条：安装该节点包 / 换一套 Workflow / 把这条能力标为不可用。你装上节点，重新校验，全绿。

右栏「能力矩阵」四行：文生图 ✅、图生视频 ✅、首尾帧 ❌、放大 ❌。下面一句话：「首尾帧缺失，依赖它的镜头无法生成」。**你在还没有任何镜头的时候，就已经知道以后哪种镜头会做不出来。**

---

## Step 5 · 剧本、Scene / Shot 与分镜板（M3）

**目标**：把叙事结构建起来。AI 可选，手动必须能走完全程。

**做的事**

- 剧本分段编辑，段落与 Scene 双向对应
- 三种模式：AI Auto / AI Assisted / Manual；LLM 产出必须逐项 Diff 审阅后才落库
- 角色名映射到已有 Character
- 分镜板：Scene 泳道 + Shot 卡片（缩略图 / 时长 / Cast / 状态 / Context 完备度）+ 拖拽排序

**使用体验（AI 路径）**

你把三千字剧本贴进左栏，点「AI 自动拆解」。等十几秒，主区出现一份 Diff：拆出 8 个 Scene、41 个 Shot，每一条前面是绿色的「＋」。你逐条看：第 3 个 Shot 的时长 AI 给了 8 秒，你改成 4 秒；第 7 个 Shot 你直接点「拒绝」。右栏「角色映射」提示「文本里的『昭儿』疑似指向已有角色『林昭』」，你确认合并——**不会凭空多出一个重复的人**。全部审完点「落库」，这才写进数据库。

**使用体验（手动路径）**

你没有配置 LLM。左栏顶部有一行灰字「LLM 未配置 · 手动模式同样可以走完全部流程」，AI 按钮禁用但「手动添加 Scene」是主按钮。你手动建 Scene，选地点变体「城南旧宅 · 雨夜」，勾出场角色「林昭（成年）」，再往下加 Shot、填时长与机位。**做出来的数据结构和 AI 路径完全一样，后续每一步都不区分来源。**

**使用体验（分镜板）**

进「分镜」，整片鸟瞰：八行泳道，41 张卡片。有 12 张右上角是灰点（草稿）、其余是空心点（就绪）。有 3 张卡片带黄色感叹号，hover 提示「缺少地点变体，Context 不完整」。你按状态筛「缺上下文」，只剩这 3 张，逐个补好。你把一个镜头从 Scene 4 拖到 Scene 3 末尾，顺序即时间顺序，卡片编号自动重排。

---

## Step 6 · Context Resolver 与镜头编辑器（M4）

**目标**：让「到底喂了什么给模型」变成可见、可改、可追的东西。这是整个系统最不能是黑箱的地方。

**做的事**

- Context Resolver：按优先级收集角色表、地点参考、道具图、前序镜头末帧
- Context Inspector：逐条列出来源、优先级、被包含或被省略的原因；支持手动移除 / 添加 / 替换 / 恢复自动
- Shot Editor 五个区：镜头信息 / 上下文检查器 / 版本轨 / Prompt 与参数

**使用体验**

你点开一个镜头。主区不是一个 prompt 输入框，而是一张清单，七行：

1. `林昭（成年）· Character Sheet v3 · 优先级 100 · 已包含` — 因为该角色在本镜头出场
2. `城南旧宅 · 雨夜 · 机位 A · 优先级 90 · 已包含`
3. `油纸伞 · 参考图 v1 · 优先级 60 · 已包含`
4. `Shot 12 末帧 · 优先级 80 · 已包含` — 用于保持连续性
5. `林昭（少年）· Character Sheet v2 · 优先级 30 · 已省略` — 原因：同一角色已有更高优先级形象
6. `城南旧宅 · 白天 · 已省略` — 原因：与本 Scene 的时间设定冲突
7. `参考图总数 4 / Workflow 上限 4 · 已达上限`

第 5 行你觉得 AI 判断错了，点「移除」换成少年形象，那一行变成手动状态并出现「恢复自动」。**你不是在猜模型看到了什么，你在看一张账单。**

底部 Prompt 区显示正负向 prompt、种子、步数。你点「生成」。

---

## Step 7 · 生成队列与版本（M4）

**目标**：批量生成可以放手不看；失败必须有明确的下一步动作。

**做的事**

- DAG 依赖调度（末帧依赖上游镜头先完成）+ 并发控制
- Pause / Resume / Cancel / Retry / 优先级调整
- GenerationVersion 只增不改，冻结当次全部参数
- 失败现场：结构化错误码 + 修复建议 + ComfyUI 原始报错 + 节点图快照

**使用体验**

你在分镜板选中整个 Scene，点「生成整个 Scene」，7 个任务入队。跳到「队列」：3 个在跑（各自带百分比进度条），4 个在等，其中 2 个的等待原因写着「等待上游 Shot 14 完成（需要末帧）」——**你知道它为什么不动，而不是以为卡住了**。

你去吃饭。回来一看，5 个成功，2 个失败。失败那条展开是结构化的：`code: COMFY_OOM`、「显存不足」、detail 写着峰值需求 19.4 GB / 可用 16 GB，建议三条：降低分辨率到 1280×720 / 改用低显存 Workflow / 关闭其他占用显存的程序。下面折叠着 ComfyUI 原始 stderr 和节点图快照。你按建议改了 Workflow，点「重试失败任务」。

回到镜头编辑器，右栏版本轨现在有 3 个版本。你把 v2 和 v3 拖到一起做 A-B 对比，选 v3「设为当前」。**v1 和 v2 还在那里，磁盘上也还在——任何一次生成都没有被覆盖。**

---

## Step 8 · 时间线与导出（M5）

**目标**：把选中的版本拼成成片。这一步必须完全不依赖 AI 也能工作。

**做的事**

- Canvas 2D 多轨时间线：缩略图条、音频波形、缩放、吸附
- 编辑命令集 + 撤销栈
- Auto-Assemble（按 Scene / Shot 顺序铺当前版本）+ Replace Version
- 720p 代理预览；导出走 FFmpeg `filter_complex`，用原始素材

**使用体验**

进「时间线」，点「自动装配」。41 个镜头的当前版本按顺序铺到视频轨上，每个片段带缩略图条，总时长显示 4 分 12 秒。你拖动播放头，预览窗立刻跟上——那是 720p 代理，所以拖起来不卡。

你觉得第 18 个镜头不好，右键「替换为其他版本」，弹出同一镜头的 4 个版本缩略图，你选 v2。轨道上只有这一个片段变了，**整条时间线不需要重排**。你按 Ctrl+Z 撤销，又按 Ctrl+Y 恢复。

你剪掉一个片段的头 0.5 秒，吸附让它自动贴到前一个片段末尾，中间不留黑帧。加两个交叉溶解转场。点「导出成片」，进度条走 FFmpeg，产出用的是原始素材而不是代理。导出完成，`generations/` 里多了一条记录，写清楚这条片子由哪 41 个版本组成。

---

## Step 9 · 项目概览与连续性检查（M6）

**目标**：项目大了之后，还能一眼知道下一步该做什么。

**做的事**

- 概览页：Scene / Shot 数量、已生成与待生成、按状态分布、总时长
- 「继续上次工作」直达最近编辑的 Shot
- 连续性检查：角色状态、时间线、道具的前后矛盾
- 最近活动 + GPU / 显存占用

**使用体验**

早上打开应用，落在项目概览。一条横向状态条：`草稿 3 · 就绪 12 · 队列中 0 · 已生成 24 · 失败 2 · 待审 0`。总时长 4 分 12 秒。右栏最近活动列着昨晚那两次失败。

你点「继续上次工作」，直接跳回昨天最后编辑的那个镜头。

你点「连续性检查」，出来三条提醒：「Shot 22 中林昭为『战损』状态，但 Shot 19 中尚未受伤」「Scene 5 标为夜晚，引用的却是白天变体」「油纸伞在 Shot 30 出现，但在 Shot 27 已被丢弃」。每条都可点跳到出问题的镜头。**它只提醒，不自动改——决策权始终在你手上。**

---

## Step 10 · 两级场景系统（替代「Workflow 为中心」的生成层）

**目标**：把生成层从「先去 ComfyUI 导一张图、再把 prompt 与参考图逐个绑到节点字段上」
换成**导演视角的两级场景系统**。模型端的图（lora、加速节点）由模型端维护，本工具不跟着改。

**做的事**

1. **应用级设置 + 配置页**：`settings.json` 压在环境变量之上（`source` 字段标出每个值来自哪），
   LLM 与视频生成 API 各一块、各自「测试连接」。**API key 永不回明文。**
2. **provider 适配层**：`VideoRequest`（`i2v` / `flf`）+ `VideoProvider`（probe / submit /
   poll / fetch）；默认核心 `comfy_preset`（按节点 title 约定注参数），通用兼容 `http_api`。
   老的 Workflow 绑定降级为兼容路径，只在 `job.workflow_id` 非空时才走。
3. **真末帧抽取**：`services/frames.py` 抽出一张 PNG 登记成 `Asset(kind="frame")`，
   `context.prev_frame` 指的就是它——不再是上游那整段视频。
4. **衔接与编排**：`SceneLink` 三种 mode（`cut` / `transition` / `tail_frame`）+
   `sequence/plan` 先出账单、`sequence/run` 才动手。
5. **第一级：幕流程图**；**第二级：场景工作台**（首帧 / 末帧 → R2V → 版本轨，本轮没有 T2V）。
6. **AI 协作栏**：读工具立刻执行、写工具只产出提案，逐条审阅采用后才落库。

**使用体验**

你新建工程，落在「幕」这一页——一条横着的链，三个还空着的节点。你在连线上那个下拉里把
第 1 幕到第 2 幕改成「转场」，第 2 幕到第 3 幕改成「续接末帧」。第三条连线下面立刻多一句话：
「上一幕的真末帧当下一幕的首帧」。

你按「先看账单」：`入队 7 个任务 · 要补 1 段转场`，下面按幕列着每一幕缺什么——第 3 幕那条写着
「上游还没有成片，会等第 2 幕出片后自动开始」。看完了才按「执行编排」。队列页里那两条 waiting
都写着在等谁，不是干卡着。

右边那一栏你跟它说「在第 2 幕后面加一幕雨夜追车」。它先看了一眼现状，然后提了三条：加一幕、
把第 1 幕改个名、把第 1 幕到第 2 幕改成转场。每条都摆着 `原来 → 改成` 和一句为什么。
第二条你不要，点叉——它就没发生过。剩下两条点「全部采用」，左边的图立刻多出一幕。
**按下采用之前，数据库里一行都没变。**

没配 LLM 的时候，这一栏不是一个红叉，是一句「去设置页填一个模型地址」+ 一个按钮；
左边手动加幕、改衔接、编排生成照旧能把片子做完。

## 里程碑与步骤对照

| 步骤 | 里程碑 | 交付后你手上多了什么 |
| --- | --- | --- |
| 1 项目容器 | M1 | 一个可拷走的自包含工程目录 |
| 2 角色与形象 | M1 | 长相固定、可派生的角色真源 |
| 3 场景 / 道具 / 资产 | M1 | 完整的素材层与文件总账 |
| 4 Workflow 管理 | M2 | 换模型不动业务数据的能力层 |
| 5 剧本与分镜 | M3 | 结构化 Scene / Shot 清单与整片鸟瞰 |
| 6 Context 与镜头编辑 | M4 | 完全透明的上下文，可手动干预 |
| 7 队列与版本 | M4 | 可放手的批量生成，永不覆盖的版本 |
| 8 时间线与导出 | M5 | 一条可导出的成片 |
| 9 概览与连续性 | M6 | 知道下一步做什么，发现前后矛盾 |
| 10 两级场景系统 | M7 | 导演视角的一张幕流程图、可换的 provider、会提案的 AI 导演 |

## 每一步的完成标准

一个步骤只有同时满足下面五条才算做完：

1. 后端接口有测试，前端 `vue-tsc` / `eslint --max-warnings 0` / `vite build` 全绿
2. 所有错误路径返回结构化错误（code / title / detail / suggestions），前端把 suggestions 显示出来
3. 每个空状态都写清「这里将出现什么」并给出下一步动作按钮
4. 不依赖 LLM 的路径能独立走通
5. `features.ts` 里对应条目的 `ready` 改成 `true`——导航栏的锁自动消失，四处入口同步生效

Step 10 在这五条之上还要多满足三条——它们是这一步特有的边界，前九步没有：

6. **业务层不知道模型叫什么**：`services/` 里不出现任何 `if provider == "..."`，
   差异只在 `app/generation/providers/*`；换 provider 不动一行业务数据。
7. **本工具不维护模型端的图**：`comfy_preset` 只按 title 约定注入入口参数，
   不解析、不校验、不改写图里的 lora / 加速节点；缺 title 报 `INVALID_WORKFLOW`
   并在建议里写清「去 ComfyUI 把该节点标题改成 X」。
8. **提案不是改动**：AI 导演的写工具只进提案缓冲区，`POST /director/apply` 之前
